## 2. 部分上线（5 项）

### 2.1 座位状态图形化 —— 形状有了，语义没对齐

文档 §6.3 要四种视觉：已提交**绿勾** / 等待中**金色「…」** / 超时弃权**降饱和 + 红「弃」** / 离线**灰度**。

线上实际：`✓`（已提交、已准备）、`✕`（弃权）、`!`（掉线）、`—`（离开）。差别：

- **「等待中」没有角标**（`badge: ''`），只有头像描边的呼吸光环 —— 而这是 5 人局里最常看到的状态，恰恰最不显眼；
- 弃权用 `✕` 而不是「弃」，与「离开」的 `—` 语义容易被混读；
- **离线没有灰度**，只有琥珀描边 + `!` 角标。

### 2.2 准备态长在牌桌上 —— 桌子在，托盘区没让位

文档 §14.2 要求准备态**占住托盘区 + 手牌区**（同一块矩形），理由是「开局发牌时整圈座位会跟着跳一下」。线上做法是 `#slots` 与 `.game-bottom` 整体 `hidden`，房间规则卡 `#tr-card` 作为独立卡片放在桌子下方。桌子本身零位移（这点达到了），但**托盘区是空的**，开局的纵向重排没有消除。

### 2.3 端覆盖 —— 竖屏三档 + 横屏两档，只剩 4:3 平板竖屏

| 端 | 状态 | 依据 |
|---|---|---|
| 竖屏 ≥1500（390×844 等） | ✅ 上线 | 线上 14/14 |
| 平板横屏（1024×768） | ✅ 上线 | 线上 14/14 |
| iPhone 横屏（844×390 / 932×430） | ✅ 已上线（v94） | `probe-table` 844×390 四区 + 两列两行 15/15 |
| 竖屏矮屏（16:9：375×667 / 360×640） | ✅ 已做（v95，未发布） | `probe-table` 375×667 / 360×640 × 4/5 人 15/15 + 斗牛 82×115 |
| 4:3 平板竖屏（768×1024） | ❌ 分流 v86 | 设计高只有 1000，与桌面归同一类（要另一套设计宽） |

### 2.4 头像放大 —— 68 固定，没有三档、没有按人数收敛

文档 §9.4 量了 56 / 76 / 92 三档，并规定 `n≥8` 时 92 自动降到 76。线上是常量 68，不可选。（人数收敛到 5 之后，8 人那条收敛规则确实不再需要，但「档位」这个能力没上。）

§11 验收标准原文：

> **托盘不缩水**：3 张及以下的组，牌面 ≥ 110×154；**5 张组 ≥ 82×115**。

用线上同一个函数（`SlotLayout.cardSize`）+ 实测输入（`BAND_INNER_W = 629`、竖屏组槽 537）算出：

| 组 | v86（无圆桌） | v87/v88（圆桌） | Δ | §11 下限 | 判定 |
|---|---|---|---|---|---|
| 比大小 1 张 | 139×195 | **114×160** | −18% | ≥110×154 | ✅ 刚好过线 |
| 十点半 2 张 | 139×195 | **114×160** | −18% | ≥110×154 | ✅ |
| 飘三叶 3 张 | 139×195 | **114×160** | −18% | ≥110×154 | ✅ |
| **斗牛 5 张（第二轮）** | **119×167** | **69×97** | **−42%** | **≥82×115** | ❌ **不达标** |
| 斗牛 5 张（平板横屏） | — | 74×103（推算） | — | ≥82×115 | ❌ |

**为什么只有 5 张掉得这么狠**：`slotLayout.cardSize()` 里 dense 的横向上限是 `bandInnerW × widthRatio`。v87 为了让 1–3 张的牌先被高度卡住、不被宽度二次卡住，把 `widthRatio` 从 0.55 提到 0.6 —— 这对 n≤3 是对的（它们先撞高度），但对 n=5 是**唯一约束**：

```
(629 × 0.6 − 8×4) / 5 = 69   ← 宽度算出来的
160 / 1.4            = 114   ← 高度允许的
取小 → 69
```

高度其实还宽裕 47%，宽度却被 0.6 的比例卡死。文档 §0 估的是 86×120（−28%），实际 −42%。
