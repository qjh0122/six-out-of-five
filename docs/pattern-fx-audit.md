# 牌型特效与场景交互：落地审计（2026-10-31）

> **📌 本文有两轮，第二轮推翻了第一轮的一个结论 —— 读之前先看这张表。**
>
> | 章节 | 写于 | 结论是否还成立 |
> |---|---|---|
> | §1–§6 | v92 | 「结算幕有特写、组牌幕没有」—— **成立**，并直接促成了 `slotTypeOf`（组槽实时牌型） |
> | §7 及其后 | v93 | 「四种牌型都真落地了」—— **被推翻**。玩家原话「我在游戏里看不到十点半/豹子/牛牛/五花牛的特效动画」 |
>
> **为什么会被推翻**：v93 的证据是 `audit-pattern-fx` 208 项 × 4 档全绿，验的是
> 「组槽胶囊 / 组光晕 / 结算卡内容」。但**结算幕跑的那支动画，从来不是原型设计里那支**
> —— 断言验的是「有动画」，玩家要的是「有那支动画」。这一轮没验到，因为没人问「特效长什么样」。
>
> v98 把原型 `.fx` 层真的搬过来之后才算完成（旋转 conic 金环 + 三道冲击波 + 14 颗粒子 + 牌型大字 + 震屏）。
> **结论：静态断言证明不了「玩家看得见」。** 这条教训比本文档里任何一条技术结论都值钱。
>
> 现行状态（哪个阶段能看到什么）以本文 §2 的矩阵为准 —— 但矩阵里标 `●` 的项，
> 含义在 v98 之后已经变成「**设计里那支**动画在跑」，不再是「有某种动画在跑」。
>
> 问题：「几种牌型的特效动画和相关前后场景的交互都真正落地了吗？」
>
> 结论（v92 首轮）：**结算那一幕真落地了，组牌那一幕几乎没有。**
> 一局 5 次结算，玩家只在那 5 个瞬间看到「豹子 / 牛牛 / 五花牛」；
> 而他在组牌上花的 60 秒里，界面一个字都没说。这一轮把组牌阶段补齐（v92）。

## 1. 把「场景」拆成五段

讨论「交互有没有落地」之前，先得把一局拆开。按玩家真实经历的先后：

| 段 | 玩家在做什么 | 对应界面 |
|---|---|---|
| **S1 组牌** | 六张手牌分进 1/2/3/5 张的组 | 手牌扇 + 组槽 + 组标签条 |
| **S2 提交确认** | 点提交，弹窗摊开三组再确认一次 | `#confirm-modal` |
| **S3 等他人** | 已提交，看别人 | 组槽锁定 + 顶栏「已提交 3/5」 |
| **S4 结算** | 逐组揭晓 + 算分 | `#result-modal`，一幕一组 |
| **S5 回桌 / 下一轮** | 弹窗关掉，接着打 | 轮次交替卡 → 下一轮发牌 |

一局里 S1 大约 60 秒、S4 合计约 15 秒（5 幕 × 3 秒）。
**时间长的那一段才是「交互」该发生的地方。**

## 3. 逐个确认「真落地」还是「看起来做了」

这一节是审计的正文。判断标准只有一条：**不看代码里有没有那个类名，看屏幕上有没有。**

### 3.1 结算幕的特写：真落地

| 环节 | 落地物 | 守它的东西 |
|---|---|---|
| 触发判定 | `winnerTypeName`（引擎 `typeName()` 的输出），不是自己重算 | `big-fx.test.js` 逐个牌型造牌验名 |
| 名字 → 样式 | `BIG_FX` 5 个键，颜色按浅底可读性选 | 同上（键与 `BIG_TYPES` 必须完全一致） |
| 横幅 | `.result-banner` 斜纹胶囊 | `probe-big-fx` 断言有高度、文字以牌型名开头 |
| 粒子 | 12 个 `<i>`，角度 12 等分，延迟含逐组错峰 | 断言 12 个角度互不相同、`ptDelay ≥ 0.18` |
| 光环 | `fxHalo` 1.15s，`animation-delay: inherit` 继承错峰 | 断言 `afterAnim === 'fxHalo'`、有实际阴影 |
| 音效 | 大牌型固定 1.12，不跟幕数变调 | 代码注释 + `probe-result-seq` |
| 降级 | 名字在 `BIG_TYPES` 但没有 `BIG_FX` 映射 → 静态横幅 | `big-fx.test.js` 第二条分支 |

**这一块是真的。** 21 条浏览器断言不是「类名存在」，是「动画在跑、颜色有值、粒子没被裁、组没出屏」。

### 3.2 组牌阶段：改前是空的

**这是最实质的缺口。** 具体证据：

- `renderSlots()` 在 v95 之前只渲染 `n/n` 进度条与十点半点数，**没有任何牌型计算**；
- 整个 `game.js` 里 `Engine` 出现次数：**0**。前端从来没做过一次牌型判定。

后果：玩家放满斗牛五张，界面只从 `4/5` 变成 `5/5`。
想知道自己是牛几，得自己凑十 —— 而这正是结算要告诉他的事，中间隔了 3 秒倒计时。

### 3.3 提交确认弹窗：改前只有牌名

`groupsSummary()` 输出的是 `飘三叶：10♥ 3♠ A♠`。
最后一眼确认的是「放了哪几张」，不是「这手是什么牌」。已补。

### 3.4 「震屏」：原型写了，线上没做 —— 判断是**不做**

`docs/circle-table-analysis.md` §13.3 写的是：

> 豹子：红金光环 + **毡面轻震** + 大字 `豹子`
> 五花牛：紫金混色 + **更强震屏** + 大字 `五花牛`

线上只有光环 + 粒子。三个不做的理由：

1. **结算弹窗是滚动容器**。对卡片做 `transform` 抖动会改变 `scrollHeight`，
   在窄横屏（结算区只有 435 设计 px）里表现为「卡片自己往下滑了一点」——
   `probe-modals-landscape` 39 条里有 6 条在守滚动，这一项会直接撞上去。
2. **表达重复**。组槽已经有了「成手脉冲 + 组光晕」，那不是通知，是奖励。
   同一件事在 3 秒后再震一次，第二次就没有信息量。
3. **真机不一定有震动**。`navigator.vibrate` 在 iOS Safari 上不存在，
   Android 上需要用户手势授权；拿它当唯一手段等于只有一半设备能看到。

### 3.5 「揭晓」独立成幕：原型有，线上合并 —— 判断是**不拆**

原型序列是 `分牌 → ①揭晓(1.4s) → ①结算(3.2s) → …`，线上合成一幕。
一局 5 次结算已经要按 5 次「下一组」，再拆一倍就是 10 次。
合并之后玩家是「一组牌 + 一个结果」同时看到 —— 这是这一版唯一比原型快的地方，
不倒退。

### 3.6 单张组「大王」：判断是**不做**

大王在单张组是绝对最大，理论上值一个「必胜」标记。不做的原因：

- 牌面已经有 `joker-glow`（大王图自带微光），**视觉上已经和其他牌不一样**；
- 单张组只有一张牌，「这是什么牌」不需要聚合判断，牌面就是答案；
- 一局只会出现一次，且出现时不加信息玩家也知道自己赢。

把「牌型胶囊」硬套到单张组，只会让四组里三组有胶囊、一组没有，看起来像漏了。

## 4. 这一轮补的三处（v92）

### 4.1 组槽放满即报牌型

`slotTypeOf(key, cards)`：飘三叶满 3 张、斗牛满 5 张时，把 `n/n` 换成牌型胶囊。

- **判定走 `Engine`**，前端不重算 —— 大王万能的解析择优也在那边，
  复算一次迟早和结算对不上（原型用 `r.t === 9` 裸数字，牛 9 被当成牛牛，18.5%）；
- **只在放满时报**：飘三叶放 1 张必然判成「散牌」，报出来是噪音；
- **顶掉进度而不是并排**：窄横屏两列档 `.slot-meta-main` 是 `nowrap`，并排会顶出格子；
- **普通牌型用中性深底**：一开始用组色，结果飘三叶的「对子」变成红胶囊，
  和旁边十点半的「爆 15」撞在一起 —— 「红 = 这组废了」的语义被稀释；
- **大牌型（`BIG_FX` 那 5 个）**：牌型色实底 + 一次 `slotTypePop` 脉冲 + 组本身一次光晕。

### 4.2 脉冲不会循环

`slotTypeSeen` 记住「上一次真正写进 DOM 的牌型」，只在变化时挂 `is-new`。
**关键在提交时机**：只在 `html !== lastSlotsHtml` 的写入分支里提交。
提前更新的话，「内容没变 → 跳过重写」那一帧会把状态吃掉，下一帧就判不出「刚成手」，
脉冲永远不放 —— 而且这个 bug 在静态代码里完全看不出来。

### 4.3 提交确认弹窗带牌型

`groupsSummary()` 每行追加 ` · 牌型名`，单张组除外（`Engine.typeName('single', …)`
返回的就是那张牌的名字，会重复）。

## 7. 真跑复核（v93）：四种牌型从组牌到回桌，逐帧验一遍

§1–§6 有一个共同的软肋：**证据都是「代码里写了」和「我在本地拼一段 DOM，CSS 画得出来」**。
两者之间隔着好几环 —— 引擎给不给这个名字、结算数据带不带 `winnerTypeName`、
`BIG_FX` 的键有没有拼错、组槽的胶囊会不会被 `slot-meta-main` 的 `nowrap` 顶掉。
任何一环断了，前面两条证据都不会红。

所以补了 `scripts/audit-pattern-fx.js`：**只替换牌堆顺序，其余全是真的**。

| 环节 | 是不是真的 |
|---|---|
| 发牌 | 真 `stateMachine.dealAll`（只是 `Card.shuffle` 的顺序被指定） |
| 提交 | 真 `submitGroups` 校验（必须用满 6 张、不能有手牌以外的牌） |
| 结算 | 真 `engine`，`winnerTypeName` 就是它算的 |
| 传输 | 真 WebSocket 广播 |
| 渲染 | 真 Edge，真 `computedStyle`，真动画 |
| 判定 | 全程没有一行前端复算 |

### 7.1 三把牌覆盖四个牌型

一把 = 两轮，**第二轮沿用第一轮的手牌**，所以「这一把能出现哪个牌型」是设计出来的，不靠运气。

| 把 | 手牌 | 第一轮 | 第二轮 |
|---|---|---|---|
| 1 | A♠ A♥ A♦ 10♠ J♥ 5♣ | 5♣ / **10.5 点**（10♠+J♥）/ **豹子** | 没牛（对照） |
| 2 | J♠ Q♥ K♦ J♥ Q♠ K♣ | 顺子 / 1 点 / 顺子（对照） | **五花牛** |
| 3 | 5♣ 5♦ 10♠ 10♥ J♥ 9♣ | 9♣ / 10 点 / 对子（对照） | **牛牛** |

第一把故意让**同一场结算里出现两个大牌型**：逐组推进时每一幕的特效必须各归各，
不能出现「第二幕的粒子串到第三幕」。四个 AI 的牌固定成 rank 2/3/4/6/7/8：

- 没有 10、没有 JQK → 凑不出 10.5，也凑不出五花牛；
- 任意五张的和都是 22~28，绝不 ≡0 (mod 10) → 凑不出牛牛；
- 六张 rank 互不相同 → 凑不出豹子。

也就是说这四个牌型只可能出现在「我」这一家，**特写挂谁没有歧义**。
这条在 Node 端用真引擎跑了一遍自检（6×5 子集 + 15 组对子 + 20 组三张），
自检不过就不启动浏览器。

### 7.2 逐帧结论

| 阶段 | 10.5 点 | 豹子 | 牛牛 | 五花牛 |
|---|---|---|---|---|
| **S1 组牌** | 满分绿徽标 + 成手脉冲 + 组光晕（v93 补） | 胶囊 `is-big` + `slotTypePop` + 组光晕 | 同左 | 同左，且用 `#8B5CC7` |
| **S2 提交确认** | 「· 10.5点」 | 「· 豹子」 | 「· 牛牛」 | 「· 五花牛」 |
| **S3 等他人** | 4/5 → 5/5 全员提交即结算 | 同 | 同 | 同 |
| **S4 结算幕** | 横幅「10.5点！」+ 12 粒子 + `fxHalo` + `win@1.12` | 同 | 同 | 同 |
| **S5 回桌** | 第一轮 → 交替卡（本轮净得 + 下一轮比什么）；第二轮 → 回桌/下一把 | 同 | 同 | 同 |

结算幕每一幕都实测了：`data-hold = 3000`、`--hold = 3000ms`、
12 颗 `--a` 角度互不相同（绕圈炸开而不是一条线）、粒子延迟 ≥0.18s（错峰没被吞）、
`::after` 的 `fxHalo` 在跑、`win-row` 恰好 1 行、组卡底边没有溢出滚动容器、
相邻两幕间隔 2.4~4.2 秒。

四档视口各跑一遍，全部 208/208：390×844、375×667（紧凑档）、844×390（横屏，
粒子走 `fxBurstTight`）、1280×800（桌面）。

### 7.3 真跑查出来的唯一产品缺口：10.5 在组牌阶段没有任何成手信号

| | 10.5 点 | 豹子 / 牛牛 / 五花牛 |
|---|---|---|
| 有牌型名 | 是（就是点数） | 是 |
| 贴胶囊 | 不贴（会和小绿标说同一句话） | 贴 |
| 有 `is-big` / `--fx-color` | **没有** | 有 |
| 成手那一帧有脉冲 | **没有** | 有（`slotTypePop`） |
| 整组光晕 | **没有** | 有（`slotFreshGlow`） |

原因很具体：`is-fresh` / `--fx-color` / 脉冲全部挂在 `typeName && typeFx` 上，
而 `slotTypeOf('tenhalf', …)` 按设计返回 `''`。**不贴胶囊是对的，连成手信号一起没有是漏的** ——
四个大牌型里它是唯一一个「凑到顶了界面毫无反应」的。

修法：给 `typeFresh` 一个**合成名**。`seenKey = typeName || (bestNow ? '10.5点' : '')`，
`typeFx` 在 `bestNow` 时取 `BIG_FX['10.5点']`。于是：

- 胶囊仍然不出（渲染那一路看的是 `typeName`，为空 → 照旧走 `n/n` 进度）；
- 组光晕、牌型色、徽标脉冲全都复用同一套判定，**不为十点半再养一份 seen 表**；
- 徽标脉冲用的是**同一支** `slotTypePop`（没有新写关键帧）—— 四个大牌型的成手必须是同一个动作。

### 7.4 两个观测陷阱（差点把「有」报成「没有」）

1. **25ms 轮询抓不住 `is-new`。** 点下最后一张牌那一刻是同步改 DOM：新节点带着
   `is-new` 插进来，紧接着 `ResizeObserver` / 下一次 `render` 又把内容相同的那段写一遍
   （这次 `typeFresh` 已经是 false）。带 `is-new` 的节点寿命可能不到一帧。
   第一次跑就是这样把「豹子」误判成「没有脉冲」。改用 `MutationObserver` 之后立刻变绿 ——
   **这不是产品 bug，是观察方式不够细**。以后验这类「一帧类名」只能用它。
2. **`animationName` 被后续采样覆盖。** 徽标那边无条件赋值，最后一次采样（动画已播完、
   节点也换了）把 `slotTypePop` 覆盖成了 `none`。改成「只在带 `is-new` 那一帧读」。
   胶囊那边本来就是这么写的，徽标这里漏了 —— 同一份观察代码里两处写法不一致，就会一边绿一边红。

### 7.5 顺带撞出来的两件事

- **下一把的牌堆必须在「第二轮结算」之前写好。** 结算一落地服务端就 `dealAll`，写在整把结束之后，
  第二把拿到的还是第一把的牌（探针自己的断言当场抓到）。
- **见底会走一条不同的收尾路径。** 五花牛一轮收 4 分/人，很容易把 20 分起步的 AI 打到 0 →
  进结账页 → 点「开始下一局」→ 回房间 → 再点准备，才发下一把。
  第一版只等「直接回桌」，于是在第 2 把卡死。这条链路本身也是 S5 的一部分，现在一起验了。

## 8. 特写幕（v98）：上一轮判「落地」判错了，错在哪

上一轮（v97）的结论是「S1–S5 × 四种牌型全部 ✅」，依据是
`audit-pattern-fx` 208 项 × 4 档全绿。**这个结论是错的**，玩家的反馈很直接：
「我在游戏里看不到十点半 / 豹子 / 牛牛 / 五花牛的特效动画。」

### 8.1 错在拿自己的实现当基准

v83 做「牌型特写」时，落的是原型 `.fx` 层的**组内版**：

| 原型 `docs/prototypes/circle-table.html` 的 `.fx` | v83~v97 线上实际有的 |
|---|---|
| `.fx` 整层，铺在毡面上、**结算卡不在场** | 无（特写只是结算卡内的装饰） |
| `.halo` 920×920 conic-gradient 旋转金环，7s 无限 | 无 |
| `.cards` 赢家牌重画 104/94/84 宽，逐张 `cardDrop` 从 −110px 落下 | 无（只有结算行里的 88×124 迷你牌，静态） |
| `.lbl` 108px 牌型大字，`lblIn` 从 2.3 倍砸进来 | 一条 **20px** 的金色胶囊 `bannerIn` 从左滑入 |
| `.wave` 三道冲击波 0.22 → 5.2，错峰 0/0.14/0.28 | 无 |
| `.pt` 14 颗粒子沿射线飞 170~305 | **12 颗**飞 74px（横屏 38px），且被限制在卡片内 |
| `.mkb` 牛牛「凑十的三张」金圈 + 「10」徽标 | 无 |
| `.felt.shake` 豹子 / 五花牛震桌 | 无 |

也就是说：**不是「动画没跑」，是「跑的从来不是设计里那支动画」。**
而当时的断言问的是「`bannerIn` / `fxBurst` / `fxHalo` 有没有跑」——
那三个名字是我自己写的小动画，不是设计的名字。断言与设计之间没有一条线连着，
所以绿了五个版本。

**教训（已经写进 `pwa/test/pattern-fx.test.js`）**：
验收基准必须是原型文件本身，不是实现者自己的命名。新测试的第一节直接从
`docs/prototypes/circle-table.html` 里读 `@keyframes` 与尺寸常量，
线上 `.pat-*` 必须逐个对得上号 —— 原型删了什么，这里才敢删什么。

### 8.2 移植后的形态

- 幕：`#pattern-fx`（`#stage` 的直接子节点，`z-index:52`，跟着 750 设计稿整体缩放）；
- 时机：**逐组结算的每一幕**，条件是「赢家牌型命中 `BIG_FX`」+「这一幕没放过」+ 开关打开；
- 时长：`PAT_FX_MS = 1600`（原型自我约束：一局放 3~5 次，超过 1.6 秒就烦）；
  这一幕的总停留 = `hold + 1600`，`data-hold` / `--hold` / 脚注文案 / 定时器同源；
- 结算卡在特写期间是 `opacity: 0`（`#result-modal.is-hero`），**不关弹窗**：
  关了再开一张白卡会闪，而且探针会看到「结算弹窗反复开关」；
- 可跳过：点幕任意位置立刻收幕（`is-out` 0.22s + 卡同步淡入）；
- 可关：`CONFIG.PATTERN_FX` / `?patternfx=0` / `?fx=0` / 系统「减少动态效果」。

三处与原型**有意保留的差异**（都是为了线上这个形态，不是偷懒）：

| 差异 | 原因 |
|---|---|
| 震的是整块构图（`.pat-core`），不是毡面 | 线上这一层已经盖住了桌子，震桌子在幕布后面看不出来 |
| 特写盖在结算卡上，而不是把卡收掉 | 原型的结算明细是牌桌下方常驻列表；线上结算卡就是那一屏的全部内容 |
| 10.5 幕上写「10.5」，不写引擎名「10.5点」 | 牌型名本身就是点数，再加「点」是把同一件事说两遍；只改显示，查表仍用引擎名 |
