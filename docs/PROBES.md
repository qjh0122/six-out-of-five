## 为什么不是「全部塞进 CI」

42 个探针里只有 5 个在 CI 里。这个差距看着像欠账，但直接补齐是错的：

| 理由 | 具体数字 |
|---|---|
| **大量重叠** | `probe-ui-flow` 已经在 12 个视口 × 13 屏上量过布局，`journey` 走完整条玩家路径（158 项）。`probe-devices` / `probe-table` / `probe-room-actions` / `probe-landscape*` / `probe-type-scale` 量的是同一批东西 |
| **一次性脚本** | 19 条的文件头自己就写着「一次性诊断脚本」。它们的价值是**当时怎么查的**，不是回归网 |
| **反馈时间** | 全量串行跑一轮是**分钟级到二十几分钟**（每个探针都要起服务端 + 浏览器）。CI 的 ui-probe 现在每片约 5 分钟；推到 20 分钟以上的直接后果不是更安全，是**没人看** |
| **测不准** | 安全区（`probe-safearea`）、旧内核 flex gap（`probe-flex-gap`）、PWA 全屏贴合（`probe-viewport-fit`）在 CI 的 Linux + 桌面 Chrome 上恒为同一结果，跑一万次也不会红 |

所以真正的判据不是「进没进 CI」，而是**「有没有人知道它现在还绿不绿」**。
这份台账就是回答这句话的：每条都有归属，`ci` 的由 CI 保证，`manual` 的由发版前那一遍保证，
`oneshot` 的明确承认不保证。**被承认的不保证，好过假装都在管。**

### 什么情况下应该把一条 manual 收编进 CI

三个条件同时成立才收编，缺一条都会让 CI 变慢而不变可靠：

1. 它守的东西**单测和 journey / ui-flow 都覆盖不到**；
2. 它自己**稳定**（连跑 3 次不红、断言项数不变）；
3. 单次运行 **≤ 60 秒**。

`probe-tenhalf` 就是被第 2 条挡住的例子：连跑时出现过一次 35 项 4 红，
两次重跑都是 39 项 0 红。不可复现的红进了 CI，只会教人学会忽略红色。

### v129 当时的判断（错的那一版，保留作对照）

> 根因只有两个：v103 建房两步、结算/顶栏文案改口径。v110 修好的 8 个里有 6 个又以同样的原因红了回去。

错在哪：**漏了 v111 的存储键改名**（`weile_*` → `lxw_*_v1`）。产品侧写了 `migrate()` 把老键搬过来、
自己的测试也覆盖了，**但「外部读取方」（探针、任何直读存储的脚本）没跟上**。
`npm test` 全绿，因为 `storage.test.js` 测的是「产品自己能搬」—— 它管不到别人还在读旧键。

代价：三个人读同一份台账，得到同一个错因。**所以修复要落在「类」上，不是「条」上**：
只改这 3 个探针 → 下次任何存储收口又会静默杀掉一批脚本，而我们会再误诊一次。

### 这个仓库第一次跑完全量，值得记一句

此前最后一次全量是 v108（36 个探针 25 绿 / 10 红，见 `review/2026-11-01-v108.md`），

结论只有一句：**修一次不是解，进执行链才是。**

## 怎么跑

```bash
node scripts/run-probes.js                 # 全量（串行，约 20 分钟）
node scripts/run-probes.js tenhalf leave   # 只跑名字含 tenhalf / leave 的
node scripts/run-probes.js --list          # 只列清单
node scripts/probes.js --check       # 校验台账与磁盘 / workflow 是否一致
```

**不要并行跑两个探针**：它们各自起一个 HTTP 服务（端口写在脚本里）和一个 CDP 连接，
撞上端口后的症状是「昵称已经被别人用了」这种误导性失败 —— 看起来像功能坏了，其实是自己踩了自己。
