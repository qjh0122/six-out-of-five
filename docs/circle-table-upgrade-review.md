## 4. 问题清单

### P0-1 「两轮打完 = 本局结束」与线上不一致（要拍板）

- 线上：`stateMachine.settleRound()` 第二轮结算后**无人见底 → `handCount+1; dealAll; ROUND1_SPLIT`**，继续下一把，**分数延续**。只有 `score <= 0` 才 `SETTLED`。
- 原型：`buildScenes()` 跑完 R1 三组 + R2 两组直接 `final(reason:'end')`，文案「两轮打完 · 本局结束」，回准备且分数从起始分重算。
- 影响：玩家会以为「打两轮就散场、要重新准备」，而线上核心是「一把接一把打，谁先见底谁出局」。**「见底才结束」这条规则在原型里只剩 A 场景的 4 幕能看见。**
- 建议：明确产品意图。若沿用线上，原型 `buildScenes` 在 R2 无人见底时应生成「下一把分牌」而不是 `final`，房间卡上的「起始分」也要写 20（线上 `INITIAL_SCORE`），现在写 4 是为了演示见底。

### P0-2 人数 2–5 只在原型，线上仍是 8

- `pwa/js/config.js` `MAX_PLAYERS: 8`，服务端校验、座位表、`stateMachine` 的 8 人注释都还是 8。
- 影响：这次是「设计稿先收窄」，落地要动配置 + 服务端校验 + 座位表上限，不是纯 UI。
- 建议：把「2–5」写进需求单，和 `MAX_PLAYERS` 一起改，别只改原型。

### ✅ P1-1 横屏 5 人结算条：第 5 行副标题被裁（已修）

- 证据：`ls-5settle` 量到 `listH:356` / `rowsH:359`，溢出 3px；断言阈值 `ov > 3` 才报，**正好卡在边界被放过**。截图里第 5 行「已提交 · 已结算」下半截不见了。
- 成因：`sstripHTML` 行高 `(tray.h - 104 - 4×6)/5 = 67`，5×67+4×6 = 359 > 可用 356。
- 影响：横屏 5 人局每组结算都出现一次；改成逐组结算后，暴露频率从「一轮一次」变成「一组一次」。
- 修法：`reserve` 104 → 112，或把行高改成 `floor((listH - (n-1)*gap)/n)` 用真实可用高算。顺手把容差从 `>3` 收紧到 `>0`。

### ✅ P1-2 牛9 会被当成牛牛放特写（新功能缺陷，已修）

- 证据（`review-rule-parity.js` 用例①）：
  ```
  原型 evDouniu → t=9 label=牛 9
  引擎 douNiuType → type=8 name=牛9
  原型 specialOf → nn / 牛牛   ← 牛9 放了「牛牛」特写
  ```
- 成因：`evDouniu` 里 `if (niu === 0) return { t:9 }`，牛9 走 `return { t:niu }` 也是 9；引擎编码是 `牛牛=9 / 牛9=8 / 牛8=7 …`。原型 `specialOf` 用 `r.t === 9` 认牛牛，于是牛9 中招。
- 频次：随机对撞 800 组，不含王 **148 次（18.5%）**、含王 105 次（13.1%）误播。
- 影响：演示用的 5 组固定牌**不受影响**（R2 赢家是五花牛），但任何真人局的牛9 赢都会放错动画，同时 `perPlayerPoints` 的 `t===9 → 3 分` 会把牛9 按牛牛档多收 1 分。
- 修法：`evDouniu` 改成 `t = niu === 0 ? 9 : niu - 1`，`perPlayerPoints` 的档位判断改成 `t===9 / t>=7 / t>=0`，与引擎对齐。

### ✅ P1-3 斗牛「没牛」罚分无条件加（原型规则错，已修）

- 证据（用例②）：
  ```
  两人都没牛，赢家 没牛（引擎 type=-1）
  原型 delta {"me":-6,"s0":6}（基础 1 + 无条件罚 5）
  引擎 delta {"me":-1,"s0":1}（赢家没牛 → 不罚，只收 1）
  ```
- 成因：`runGroup` 里 `if (mode === 'douniu') entries.forEach(e => { if (e.k !== win.k && e.r.t < 0) 罚 5 })`，缺 `winnerHasCow` 前提。引擎是 `base + (winnerHasCow && !eHasCow ? 5 : 0)`。
- 频次：同赢家但分数不同 800 组里 250 次（不含王 31.3%）。
- 影响：全桌都没牛时，输家被多扣 5 分。演示牌组不受影响（赢家五花牛，有牛）。
- 修法：补 `winnerHasCow` 判断。

### ✅ P1-4 牛牛有特写，但结算条没有橙色标签（已修）

- `sstripHTML`：`var spec = i === 0 && (e.r.t >= 10 || e.r.t === 6 || e.r.jokerWin);`
- 斗牛里 `t >= 10` 只覆盖五花牛，**牛牛 t=9 漏了**；而 `specialOf` 会给牛牛放特效。
- 结果：牛牛赢 → 动画有、行内红标没有；正好和文档写的「标签跟着动画走」相反。
- 修法：与 P1-2 一起改，`spec` 用 `specialOf(mode, e) != null` 判定，别另写一套条件。

### ✅ P2-1 飘三叶同型比花色取的是「第一张牌」的花色（已修，且是**判赢错误**，不只是精度问题）

- `evPiao`：`key.push(SUIT_ORD[cards[0][1]])` —— 用的是手牌原始顺序第一张，不是决胜牌。
- 影响：散牌/同花/顺子同点时胜负可能判反。不含王 6.0%、含王 18.0%（含王还有另一个原因：原型完全不支持飘三叶的王）。
- 修法：改用 `rs` 对应的那张牌的花色，或直接对齐 `comparePiaoSanYe`。

### ✅ P2-2 十点半双爆同点缺一层花色比较（已修）

- 原型 `key = [bust?0:1, rank, maxV]`，`maxV` 相同就判平，靠数组顺序定赢家；引擎 `compareTenHalf` 会继续比「贡献点数最大的那张」的花色。
- 影响：2~3.5% 的组，赢家可能是数组里排前面的那个。
- 修法：`key` 补上决胜牌花色。

### ⚠️ P2-3 斗牛完全不处理大王（**未修**，见 §8.3）

- 原型 `niuPoint(joker) = 10` 且 `five` 判断排除王；引擎有 `douNiuInfoJoker()` 两条路（王去补牌 / 王不参与凑十）。含王时胜负差异 **28.1%**。
- 影响：演示牌组不含王，所以看不出来；线上 53 张牌，斗牛一定会有王。
- 修法：原型不必实现全套，但**必须在文档里标注「原型斗牛不支持王，落地以 engine 为准」**。

### P2-4 文档附录过时

- `docs/circle-table-analysis.md` 第 659–660 行仍写「切 2 / 3 / 5 / 8 人」「8 人 + 大会看到自动收敛」，与「已取消 6/8 人档」自相矛盾。
- 修法：改成 2/3/4/5，并删掉 8 人收敛的描述。

### P2-5 「起始分」两处口径不一

- 房间牌 `roomHTML` 写「底分 1」，规则卡 `roomInfoHTML` 写「起始分 4 分」（A 场景演示值）。
- 「底分」是单张赢 1 分，「起始分」是开局的分数，两个概念并排容易被读成同一件事。
- 修法：房间牌改成「单张 1 分」或直接删掉，只保留规则卡一处。

### P2-6 个人信息面板没有「换头像」入口

- 换头像只能从侧栏调试按钮进（`btn-avatar`），产品界面上没有入口；准备态合并后也没补。
- 如果线上房间页原来有头像设置，这就是一条丢失的入口，需要确认。

### P2-7 表情网格可滚动 2px

- 截图量到 `gridScroll:528 / gridClient:526`（桌面、横屏）、`468/466`（竖屏），说明面板里那 13 格比容器高 2px，能拖动一点点。
- 修法：格子高度取整时向下取，或 `padding` 少 2px。

### P2-8 代码卫生

- `S` 里 `phase` 定义了两次（`'split'` 在第 1311 行、`'ready'` 在第 1329 行），后者覆盖前者，`'split'` 是死字段。

### 8.4 这一轮的教训

P2-1 / P2-2 原先被我判成「不影响演示的精度问题」，实际是**判赢错误**：`6♦A♠2♣` 对 `9♣3♦A♥` 会被判后者赢，而正确结果是前者。判赢错和展示错不是一个量级——展示错只是不好看，判赢错会让输家完全无法理解自己为什么输。

差分脚本的价值就在这里：它不看画面，只看数值，所以能抓到「截图永远绿」的地方。

### 8.5 架构收口：原型不再有第二份规则实现（同日完成）

**原委**：P2-1 / P2-2 的根因不是「抄的时候不够仔细」，而是**同一套规则存在两份实现**。
`engine.js` 头部第一行就写着「本文件同时被两处使用（**同一份代码，不复制**）」，
它又是 UMD（`global.Engine = mod`），浏览器里 `<script src>` 直接就是全局 `Engine`——
引用成本为零。而我手抄了一份 154 行的精简版，压掉了王的分支和逐张比花色的兜底层。
