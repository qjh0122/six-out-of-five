## 1. 结论先说

iPhone 横屏能上圆桌，但**不能沿用现在的「三组竖排」**。

| 排法 | 组槽可用高 | 牌面（设计 px） | 牌面（CSS px，scale 0.52） | 判定 |
|---|---|---|---|---|
| 三组竖排（现状 v88 逻辑） | 232 | 60×84 | **31×44** | ✗ 认不出牌 |
| 三组竖排 + 四区网格（腾出组标签条） | 326 | 64×90 | **33×47** | ✗ 仍然认不出 |
| 今天线上（不上圆桌） | 502 | 105×147 | 55×76 | ✓ 但不是圆桌 |
| **两列两行 + 四区网格（本方案）** | 326 | **104×146** | 55×76 | ✓ 与今天持平 |

关键结论：**三组竖排在 326 高里每题只有 102，扣内边距只剩 90**，牌高被高度卡死
（`maxCardHeight` 是纯高度函数，横向再怎么宽也没用）。想保住牌面，就必须把
三组压成**两行**——横向借地，纵向才够。

## 2. 实测数据（844×390，设计 1624×750，scale 0.52）

### 2.1 纵向预算

设计高 750 − 上下 padding 48 = **702**。右栏要竖着装四样东西：

| 块 | 高（设计 px） | 说明 |
|---|---|---|
| 组标签条 `#group-chips` | 88 | 四个标签 + 清空 |
| 组槽 `#slots` | ? | 弹性 |
| 手牌 `#hand` | 268 | 固定 |
| 操作条 `.game-actions` | 88 | 三个按钮，已顶到 44 CSS 触摸下限（44/0.52 = 85），**不能再缩** |
| 行间距 | 20 | 两处 × 10 |

702 − 88 − 268 − 88 − 20 = **238**。而三组竖排按最小牌高也要 **305** → 溢出 67。

### 2.2 把组标签条搬到左栏之后

**实测（临时放开闸门 + `.game-bottom{display:contents}`）**：

```
top（桌子）   550 高，左栏 702 里居中，余 152
slots         326，scrollH 326，overflow 0   ← 三组放得下了
hand          268 / actions 88 / chips 88（左栏第三行）
cardBox       64 × 90  ← 问题在这
```

组槽够了，但牌只有 64×90。原因：dense 三行均分 `(326 − 20) / 3 = 102`，
`maxCardHeight` 扣掉内边距 12 = **90** → 宽 = 90 / 1.4 = 64。
**这是高度约束，不是宽度约束**，把组槽拉宽一点用都没有。

### 2.3 两列两行的算术

组槽 326 → 两行各 158。用 dense 口径（组信息在牌右侧，`metaV = 0`）：

```
maxCardH = 158 − padV 12 = 146  →  w = 146 / 1.4 = 104
```

横向：右栏 798，两列各 352（扣列间距 10）。

| 组 | 张数 | 需要的宽 | 352 够不够 |
|---|---|---|---|
| 比大小 | 1 | 104 | ✓ |
| 十点半 | 2 | 104×2 + 8 = 216 | ✓ |
| 飘三叶 | 3 | 104×3 + 16 = 328 | ✓（352 差 24 余量） |
| 斗牛 | 5 | 104×5 + 32 = 552 | ✗ 跨两列整行（714 → 每张 136 ✓） |

于是每轮的排法自然落成：

```
第一轮（1 / 2 / 3 张）        第二轮（1 / 5 张）
┌──────────┬──────────┐      ┌─────────────────────┐
│  比大小   │  十点半   │      │       比大小         │
├──────────┴──────────┤      ├─────────────────────┤
│       飘三叶         │      │        斗牛          │
└─────────────────────┘      └─────────────────────┘
```

两轮都是两行，行高一致，**换轮不会跳一下**。

### 2.4 桌子这一侧

左栏 800×702：桌子 800 宽 → `rx 340 / ry 209 / h 550`，居中后上下余 152，
正好放组标签条（88）+ 64 的呼吸位。环内 5 个座位在 800 宽下的弧长间距
已经由 `pwa/test/seat-ring.test.js` 钉住（≥ 头像直径 68 + 4），这一档不需要重算。

## 3. 实现拆分

### S1 · 四区网格（CSS，约 1 小时）

```css
.ls #screen-game.rt-narrow {
  grid-template-columns: 800px minmax(0, 1fr);
  grid-template-rows: minmax(0, 1fr) auto auto;
  grid-template-areas:
    "top slots"
    "top hand"
    "chips acts";
}
.ls #screen-game.rt-narrow .game-bottom { display: contents; }
```

`display: contents` 是这一步的关键：`#group-chips` 现在被包在 `.game-bottom` 里，
不这样它没法单独落到左栏。实测有效，且**不需要搬 DOM** —— 搬 DOM 要处理
重渲染顺序和回滚，成本高一个量级。

必须一起处理的两件事：

- `.game-bottom` 的 `display:contents` 让它的 `padding-top:28` / `gap:12` /
  `justify-content:center` 一起失效，手牌居中要落到 `#hand` 自己的 `margin:auto`；
- `.rt-narrow` 与 `.rt-ring` 是**两个类**：宽屏（≥1000）继续用 v88 的三行右栏，
  窄屏用四区。共用 `#game-top.gt-ring` 那一整套，不复制桌子样式。

### S2 · 组槽两列（`slotLayout.js` + `game.js` + CSS，约 3 小时）

新增一种排法，而不是改 `dense`：

```js
// METRICS 里加一档 twoCol：组信息在牌右侧（metaV 0），两行
var METRICS = {
  normal: { gap: 12, padV: 14, metaV: 55, widthRatio: 1, rows: 3 },
  dense:  { gap: 10, padV: 12, metaV: 0,  widthRatio: 0.55, rows: 3 },
  twoCol: { gap: 10, padV: 12, metaV: 0,  widthRatio: 1, rows: 2 }
};
```

- `maxCardHeight` 的 `GROUPS=3` 换成 `rows`（对 twoCol 传 2）；
- `cardSize` 的 `bandInnerW` 按**单元格宽**传（352），斗牛那种跨列的传整行；
- `game.js` 加一张「本轮哪几组占哪一格」的表：

```js
var TWO_COL_SPAN = {
  1: { single: 1, tenhalf: 1, piaosanye: 2 },   // 值 = 占几列
  2: { single: 2, douniu: 2 }
};
```

- CSS：`#slots` 在这个档下 `display:grid; grid-template-columns: 1fr 1fr;`，
  `.slot[data-span="2"] { grid-column: span 2 }`。

### S3 · 闸门与档位切换（`game.js`，约 1 小时）

`seatRingFlag()` 现在只有一道「横屏 ≥1000」。改成两档：

```js
// 横屏两档：≥1000 走 v88 三行右栏；700~1000 走四区 + 两列组槽
var RING_MIN_LS_STAGE_H = 700;   // 844×390 = 750 / 932×430 = 749
```

另外补一条**按 scale 的闸门**：`scale < 0.5` 时按钮够不到 44 CSS px
（667×375 的 0.41 就是被这条挡住的）。把「设计高」和「触摸尺度」拆成两条判据，
比现在用一个 1000 兼顾两件事更清楚 —— 以后要动任何一条都不会互相牵连。

### S4 · 断言（约 2 小时）

| 位置 | 新增 |
|---|---|
| `pwa/test/seat-ring.test.js` | 两档判据、`.rt-narrow` 网格接线、两列跨度表 |

## 4. 风险

| 风险 | 兜底 |
|---|---|
| `display:contents` 在旧 WebView 上行为不一致 | iOS 11.1+ / Chrome 65+ 支持；本项目最低目标 iOS 13。真机验一次即可 |
| 两列组槽与「点组标签 → 选中态」的视觉关联变弱（标签在上、两组并排） | 组色条保留在每格左上；标签条现在在左栏，需要一次截图确认不别扭 |
| 组信息从「牌下方」搬到「牌右侧」后，横屏下每格只有 352 宽 | 已有的 dense 就是这套（v80 起用），复用不新写 |
| 46 处源码级断言可能因 `#slots` 结构变化而红 | 先跑 `npm test` 拿清单，逐条改口径而不是删断言 |

**回滚**：`CONFIG.SEAT_RING = false` / `?seatring=0` 仍然一键回到 v86；
`?seatring=1` 在窄横屏上继续可以强制预览（后果自负：三行会溢出）。

判定标准只有一句：**iPhone 横屏上的牌面不低于 100×140 设计 px**。
低于它，宁可继续不上桌子。

## 6. 与 v88 的关系

v88 的闸门（1000）写在 `seatRingFlag()` 里，注释里那段「差 69，两条退路都试过」
说的是**三组竖排**这条路的尽头。这一期没有推翻那个结论，而是换了排法：
把「三组竖排」换成「两列两行」，纵向从 3×102 变成 2×158，牌面从 64×90 回到 104×146。

那段注释要一起改，否则下一个人读到的还是「iPhone 横屏上不了」。
