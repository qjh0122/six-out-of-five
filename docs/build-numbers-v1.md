## 1 · 裁定（六条，都是我在设计和实测之间拍的）

### N1 · 判据从「数几个」改成「在不在梯子上」

设计写「同一屏内数字元素的 font-size 去重后 ≤3」，但 §③-a 自己的映射表算出来就不满足：
战绩页 = 净胜 88 + 三卡 48 + 纪录条 32 + 场次 24 = **四个字号**。原表把 40 改成 32 之后仍然是四个。
这不是施工能绕过的，是规范内部自相矛盾。

**改为阶梯封闭**：数值元素的 font-size 必须 ∈ `{88, 48, 32, 24}`，单位 ∈ `{28, 20}`。

为什么这个判据更好：`40 / 34 / 30 / 62 / 68 / 84` 这些值的共同点不是「多了」，是**不在梯子上**——
它们是一个一个长出来的（40 是"比 48 小一点"，34 是"比 32 大一点"，68 是"小屏再缩一点"）。
判「在不在梯子上」挡得住未来的新增，判「几个」挡不住。

### N2 · 阶梯只许改文档，不许在 CSS 里现编

新增 `:root` 六个 token：`--num-1/2/3/4` 与 `--num-u1/u2`。
任何 `font-size` 想写数值，只能写 `var(--num-*)`。要加档先改本文件和设计文档。

### N3 · 「数 + 量」不算数值元素

`: 25 分`、`5 次`、`/ 35`、`12 场` —— 按设计 §③-b 自己的说法，「读起来是一个词」。
它们走正文层级，不進阶梯；其中**分母 `/ N`** 归单位档 `{28, 20}`（它是 T1 的配件）。

判据因此只盯**纯数字与百分比**（`+14` / `0` / `50%`）——这些才是"一屏的结论"。

### N4 · 角标豁免

`position: absolute` 的胶囊里那个数字（`.settle-pos`：24×24 的圆，里面一个 16px 的「2」）
按**图形**处理，不进阶梯 —— 它的字号由胶囊直径决定（16px 正好居中，24px 会顶满出血）。
豁免写在断言里，不是默默跳过。

### N5 · 媒体查询可以换档，不能换到梯子外

短屏/横屏允许 `--num-1` → `--num-2`（换一档），但**不许**出现 `62`、`68` 这种梯子外的值。

**`records.css:1235` 的 `.ach-count b { font-size: 68px }` 是删掉，不是改值**：
舞台已经按屏宽 `transform: scale()` 过一遍了，`max-width: 420px` 再缩一次 = 双重缩小。
后果是**390（主力机型）比 430 的字还小** —— 这是本次实测抓到的真缺陷，不是审美问题。

### N6 · 横屏冠军不许比竖屏小

`.wide-stage .settle-row.champion .settle-net` 是 40，竖屏是 48 —— 同一个冠军、更宽的屏、更小的字。
改为同档 `--num-2`。

### R9 · 设计异议 D9 的裁定（2026-11-08，制作人）

创意总监在 `design-states-v2.md` §① 提了 D9：N5 的立法理由针对的是 **68 / 62 这类梯外缩小**，
并不针对「令牌内换档」；把 `.ach-count b` 的两条媒体覆盖整条删掉，等于顺手取消了最小机型的兜底。
并指出本单 §3.2 自留的「若 320×568 溢出，改 `--num-2` 并在提交里写明」**从未被任何断言覆盖**，
`probe-ui-flow` 的验收档最窄只到 360×640。

**裁定：异议的方向成立，落法改为「补断言」，不回退已上线的实现。**

| 项 | 结论 |

### 3.3 新建 `pwa/test/number-scale.test.js`

静态守（结算页要真打一局才能渲染，进不了探针，只能在这里守）：

1. `:root` 有六个 token，值恰好是 88/48/32/24/28/20；
2. 扫 `style.css` / `records.css`，凡选择器命中**数字白名单**（`.settle-net` `.settle-score` `.rp-*` `.rank-*` `.ach-*`）的 `font-size`，值必须是 `var(--num-*)`，**不允许直接写 px** —— 写了就等于绕过阶梯；
3. 反向：`font-size: 68px` / `34px` / `40px` / `30px` 这类字面量在命中范围内计数必须为 0；
4. **分类器自测**：给分类器喂 6 条真假样本（`40px` 命中、`var(--num-3)` 不命中、`.settle-pos` 豁免命中），
   证明它既能抓也能放 —— 否则「零违规」只说明规则没匹配上。

### 3.4 `scripts/probe-numbers.js`（我写好了，随本次一起提交）

真浏览器守战绩/排行/成就三屏，判据：数值 ∈ 阶梯、单位 ∈ {28,20}、单位严格小于数字、
同屏 T1 ≤ 1、榜单名次与净值各自只有一号。

**成就页的说明**：数据走 `RoomStore.getProfile`（WS），探针只回 ack 不回 profile，
页面会停在「正在加载」。所以探针**用页面自己的 `AV.pageHtml()` 合成一份 DOM** 塞进
`#ach-body` —— 数据是假的，DOM 与 CSS 是真的。它验的是"数字长多大"，不验数据通路
（那是 `probe-states` / `journey` 的活）。

## 4 · 必交断言（新增，且都要能红）

1. 战绩页数值全部 ∈ 阶梯（当前 9 条 40px 违规 → 0）
2. 榜单数值全部 ∈ 阶梯（当前 23 条 40/28 → 0）
3. 成就页数值全部 ∈ 阶梯（当前 68/34/30 → 0）
4. 单位只用 {28,20}，且严格小于所属数字

① `.rp-best-v b` 改回 40px → ①⑥ 红；② `.ach-count b` 恢复 `max-width:420px{68px}` → ③ 红；
③ `.rank-no` 给 top3 单独 32 → ⑥ 红；④ `.rp-unit` 改 24（小于但不同档）→ ④ 红。
