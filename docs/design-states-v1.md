## 0. 一句话结论

**今天全站只有一套页面骨架（空态那套）在兼职当"所有状态"，靠换一句标题区分"在等"和"没有"** —— 所以玩家在加载时看见的是「正在读取战绩…」＋一张 0 分的卡片＋一个能点的「创建房间」，在失败时看见的是空态标题＋页脚一句没有下文的说明。这不是文案问题，是**缺了三个"态"**。

三条证据（施工前请自己复核一眼，别信我）：

| 现象 | 位置 | 后果 |
|---|---|---|
| `loading` 只参与"改标题"，布局/插画/按钮仍是空态那一套 | `recordsView.js` `renderRecords()` 里 `loading` 只被用来把 title 换成「正在读取战绩…」，随后 `return` | 等待期间「创建房间」是可点的，玩家点进去后请求回来又把页面重画一次 —— 既是误导也是竞态 |
| 云端读失败时没有任何动作按钮，只有页脚一句话 | `recordsView.js` 页脚 `#records-source`：「账号数据暂时读不到…」 | 玩家知道坏了，但**没有出路**；只能退出重进 |
| 排行榜**有**独立的 `#rank-loading`，而失败只改 `#rank-empty` 的文字 | `index.html` `#rank-loading` / `#rank-empty`；`renderRank()` 的 `failed` 分支 | 同一件事全站两种做法 → 缺的是**规格**，不是实现能力。同时它自己也违反了下一节的硬要求：只换文案不算分成两态 |

**所以本文件不发明新组件，只做一件事：把"四态"从比喻变成四个能被断言检验的 DOM 块。**

## ① 四态定义表

### ①-a 定义

| 态 | 触发条件（精确到代码判据） | DOM 标识 | 视觉三要素 | 标题文案（≤14 字） | 副文案（≤26 字，可空） | 与另外三态一眼可分的依据 |
|---|---|---|---|---|---|---|
| **空** | 数据到手且真的没有：`hasData === false`（`st.games===0 && rows.length===0`），且不处于 loading / fail / offline | `#records-empty`（沿用现有）<br>`class="rp-empty"` | 插画：**有**，188px 内联 SVG（那张"0 分的卡"，沿用不动）<br>动作按钮：**1 个**，主 CTA `#btn-records-create`「创建房间」<br>自己走开：**不会** | 还没有战绩，去开一局吧 | 打完一局自动记下 | 全站**唯一**"有插画 + 只有一个主 CTA + 居中满屏"的态 |
| **加载** | 云端档案请求在途：`loading === true`，即 `!useCloud && !cloudRecordsErr && cloudRecordsReady()`（`renderRecords` 现有判据）。榜单侧：`#rank-loading` 可见期间（`await fetch` 未 resolve） | `#records-loading`（**新建**）<br>`#rank-loading`（沿用现有，统一视觉） | 插画：**无**，代之以 44px 金色细环（CSS `@keyframes`，**不是**骨架屏）<br>动作按钮：**0 个**（硬性：容器内 `querySelectorAll('button').length === 0`）<br>自己走开：**会**（请求回来即走） | 正在读取战绩… | *（空）* | 全站**唯一**"零按钮"的态；且它是唯一**会自己消失**的满屏态 |
| **失败** | 云端档案请求有结论地失败：`cloudRecordsErr` 非空 且 `cloudRecordsReady()`；榜单侧 `failed === true`（`!res.ok` 或 `res.json()` 抛错）。**本机还有数据时降级为页脚一行**（见 ⑤-c），本机也无数据时才独占屏 | 满屏：`#records-fail`（**新建**）<br>降级：`#records-source` 那一行 + 行内 `#records-source-retry`（**新建**）<br>榜单：`#rank-fail`（**新建**） | 插画：**无**（不给——理由见 §0 与 ④-5）<br>动作按钮：**2 个**（主「再读一次」+ 次「先开一局」）<br>自己走开：**不会**（必须留按钮，否则出路被藏） | 账号数据没读上来 | 这台设备上也没有可显示的战绩 | 全站**唯一**"两个按钮"的态；且是唯一一个**永不自愈**的满屏态 |
| **离线** | `navigator.onLine === false`（`game.js` `isOffline()` 同一判据）且当前动作/页面需要云端数据。**优先级最高**：离线时不再判 loading/失败 | `#records-offline`（**新建**）<br>`class="rp-state rp-state--offline"`<br>**两种形态共用同一个块**：<br>· strip（本机有数据）→ 贴在 `#records-foot` 上方，横条<br>· panel（本机 0 局）→ 满屏，但**保持左对齐** | 插画：**无**<br>动作按钮：**1 个**，ghost 小按钮「重新载入」<br>自己走开：**会**（`online` 事件回来 500ms 内自动收起） | 现在没有网络 | 先把这台设备上的记录给你看 | 全站**唯一**"左对齐"的态（其余三态居中）；也是唯一**允许叠加**在别的态之上的态 |

### ①-b 自证：任意两态至少两件不同

签名只看三件东西：**插画 有/无**、**按钮 0/1/2**、**会/不会自己走开**（第 4 件"对齐"作为加分证据）：

| 组合 | 插画 | 按钮 | 自走开 | 不同的件数 |
|---|---|---|---|---|
| 空 vs 加载 | 有 / 无 ✔ | 1 / 0 ✔ | 否 / 是 ✔ | **3** |
| 空 vs 失败 | 有 / 无 ✔ | 1 / 2 ✔ | 否 / 否 ✘ | **2** ✔ |
| 空 vs 离线 | 有 / 无 ✔ | 1 / 1 ✘（都是 1 个） | 否 / 是 ✔ | **2** ✔（另有对齐差异） |
| 加载 vs 失败 | 无 / 无 ✘ | 0 / 2 ✔ | 是 / 否 ✔ | **2** ✔ |
| 加载 vs 离线 | 无 / 无 ✘ | 0 / 1 ✔ | 是 / 是 ✘ | **2** ✔（另有对齐差异） |
| 失败 vs 离线 | 无 / 无 ✘ | 2 / 1 ✔ | 否 / 是 ✔ | **2** ✔ |

> 全部 ≥2。**注意"空 vs 离线"只有靠对齐才稳**——所以 ⑤ 里把"离线必须左对齐"写成硬约束，不许施工者为了好看把它改成居中。改了它就退化成"只换了文案的第二个空态"。

### ①-c 判定顺序（唯一来源）

```
offline > fail > loading > empty > data
```

- **离线压过失败**：因为离线是"原因"，失败是"结果"。先说原因，玩家才知道该修什么（去找信号），而不是去点一个注定失败的「再读一次」。
- **fail 压过 loading**：请求已经有结论了，转圈就是撒谎。
- **loading 压过 empty**：还没拿到，就不能说"没有"——**这是现状最伤的一条**：`hasData` 在 loading 期间恒为 false，所以现状在"还不知道"的时候已经摆出了"还没有战绩"。
- 建议落成一个**纯函数**：`recordsStateOf({ online, cloudErr, cloudLoading, hasData, avail }) → 'offline'|'fail'|'loading'|'empty'|'data'`。纯函数是为了能单测——四个 if 散在 `renderRecords()` 里的话，加第五态那天一定漏一个分支。

### ①-d 空态的"变体 B-2"要搬家（现有错误）

`recordsView.js` 现在有这一支：`!avail && !useCloud → 「当前浏览器无法保存战绩」/「换个浏览器或关掉无痕模式再试」`，**但它的 DOM 仍是空态那一套**：188px 的"0 分的卡"插画 + 「创建房间」CTA。

这是语义错位：**"这台设备存不了"不是"你还没打过"**，用"0 分"的插画去说"存不了"是在讲错的画面。规范：它属于**失败 · 不可恢复类**（见 ②-`err.data.no_storage`），迁到 `#records-fail`，文案换成标题「这个浏览器存不了战绩」/ 副「关掉无痕模式，或换个浏览器」/ 单按钮「照样开一局」（不出现重试字样，因为重试没有意义）。

## ② 错误三级分类表

### ②-a 三类定义与判据

**分界只有一句话：玩家再点一次，有可能变好吗？**

- 有可能 → **可重试**：给按钮，给明确动词（再读一次 / 刷新榜单 / 重新载入）。
- 没可能（是我们或环境的问题）→ **不可恢复**：给"换一条路"的按钮或干脆不给按钮，**禁止「再试一次」**。
- 玩家不需要知道 → **静默**：只写 `ErrorReport`，页面一个像素都不动。

| 类 | 判定条件（代码判据） | 文案 key | 给玩家的动作 | 允许出现「再试一次」字样？ | 需要上报？ |
|---|---|---|---|---|---|
| **可重试 · 断网** | `navigator.onLine === false` 且动作需要网络（`blockedOffline()` 的既有判据） | `err.net.offline` | 按钮「重新载入」；不弹 toast（现状 `flash` 2.6 秒一闪，见 §0 修正） | **允许**，但优先用「重新载入」——这个动词告诉玩家"会重新走一遍"，泛词做不到 | **需要**。`capture('net', 'err.net.offline', {source})`。断网下点按钮的次数是"该不该做真离线模式"的唯一依据 |
| **可重试 · 超时/中断** | `fetch` reject 或 `AbortError`（含现有 8 秒超时）。今天所有网络异常都被归成一句 `'网络不太好'`（`recordsView.js` 的 `.catch`），**这一层粒度过粗**，导致"该重试的"和"该重新登录的"长得一样 | `err.net.timeout` | 按钮「再读一次」 | **允许** | **需要**。带 `elapsedMs`（这次等了多久）——同一句"读不到"，200ms 和 8000ms 是两种故障 |
| **可重试 · 服务端 5xx / 429** | `!res.ok` 且 `status >= 500 \|\| status === 429` | `err.net.server` | 按钮「再读一次」；429 时副文案改「人有点多，过一会儿就好」 | **允许** | **需要**，带 `status`。5xx 与 429 混在一起会让"服务器炸了"和"人太多"共用一档 |
| **可重试 · 榜单读取** | `renderRank()` 里 `failed = true`（`!res.ok` 或 `json()` 抛错） | `err.net.rank` | 按钮「刷新榜单」 | **允许** | **需要**（`source: 'recordsView.js#renderRank'`）。榜单是唯一"坏了会被人立刻看见"的接口 |
| **不可恢复 · 设备存不了** | `Records.available() === false`（无痕模式 / `localStorage` 被禁 / 配额 0） | `err.data.no_storage` | 按钮「照样开一局」（不给重试按钮） | **否**。替代说法：副文案「关掉无痕模式，或换个浏览器」——把"改条件"说出来，而不是把"再点一次"说出来 | **需要**。这条决定"到底有多少人在无痕里玩"，直接决定要不要做内存兜底 |
| **不可恢复 · 身份失效** | `status === 401 \|\| 403`，或服务端明确回"档案不存在"（玩家已注销） | `err.data.auth` | 按钮「重新登录」 | **否**。替代说法：「重新登录」「这个账号已经不在了」 | **需要**，但**不带昵称、pid**（身份类错误的上下文只留 `status`，原则：上报里不放能认出人的东西） |
| **不可恢复 · 数据形状不符** | `res.json()` 抛错，或档案缺必需字段（`totalNet` / `games` 为 `undefined`） | `err.data.malformed` | **无动作**，页面按本机数据继续（页脚降级那一行照常） | **否**。替代说法：无按钮；页脚写「账号数据格式不对，先看本机的」 | **需要**（最该上报的一条：这是服务端契约变了的信号，静默上报 + 页脚降级即可，不要挡玩家） |
| **不可恢复 · 写不进本机** | `QuotaExceededError`（写战绩/写回放时抛） | `err.data.quota` | 按钮「清一下旧记录」（跳到战绩页的「清除记录」） | **否**。替代说法：「先清掉旧记录」 | **需要**。区分"从没写进去"与"写满写不进"——一个是一次性故障，一个是长期容量问题 |
| **静默 · 云端档案降级** | 云端档案读失败，但本机数据够用、页面已按本机渲染（**现有注释已经这么说了**：`recordsView.js` 上方「只记原因、不弹 toast」） | `err.silent.profile` | 无动作（页脚那句降级说明**保留**——页脚说明 ≠ 打扰） | **否**（不出现该字样，因为没有按钮） | **必须上报**。这是静默类的主场：玩家什么都没感觉到，但我们得知道"这个周末有 30% 的人是降级看的" |
| **静默 · 已注销玩家清理** | 清理查询失败（现在就是"查不到什么都不做"） | `err.silent.purge` | 无动作 | **否** | **必须上报**。误删不可逆，所以"没查成"也必须留痕，否则"为什么这人的名字还在"永远查不清 |
| **静默 · 预热失败** | 非玩家主动触发的预取（进房间时的档案预热、分享页的榜单预取）失败 | `err.silent.prefetch` | 无动作 | **否** | **必须上报**，但**每会话一次**（`capture` 自带 `seenKeys` 去重 + `MAX_PER_SESSION` 上限，见 `errorReport.js:98-100`，所以**不需要自己再写节流**——这是复用点，写新节流就是重复造） |

### ②-b 文案表（唯一来源，施工时逐字复制）

| key | 玩家看到的字 |
|---|---|
| `err.net.offline` | 现在没有网络 / 先把这台设备上的记录给你看 /〔重新载入〕 |
| `err.net.timeout` | 账号数据没读上来 / 这台设备上也没有可显示的战绩 /〔再读一次〕〔先开一局〕 |
| `err.net.server` | 账号数据没读上来 / 服务器那边没应声，过一会儿再来 /〔再读一次〕〔先开一局〕 |
| `err.net.rank` | 榜单没读上来 / 可能网络不稳，过一会儿再看 /〔刷新榜单〕 |
| `err.data.no_storage` | 这个浏览器存不了战绩 / 关掉无痕模式，或换个浏览器 /〔照样开一局〕 |
| `err.data.auth` | 登录已经过期了 / 重新登录就能看到账号里的记录 /〔重新登录〕 |
| `err.data.malformed` | *（不占标题位）* 页脚：账号数据格式不对，先看本机的 |
| `err.data.quota` | 本机存不下了 / 清掉一些旧记录就能继续记 /〔清一下旧记录〕 |
| `err.silent.*` | *（不出现任何文字）* |

**禁用词（出现在任何玩家可见位置都算施工不合格）**：`操作失败` / `请稍后重试` / `网络异常` / `请求失败` / `系统繁忙` / `错误码 1023`。
理由不啰嗦：这些话的共同点是**把责任和下一步都推给玩家**。现有文案的语气不是这样——「还没有战绩，去开一局吧」「账号数据暂时读不到，先显示这台设备上的记录」都是"我告诉你现在是什么、我替你安排了什么"。

### ②-c 我今天要反对的一条

任务要求"不可恢复类必须写'否'"（不许出现「再试一次」）——我同意，但**我要把这条扩大到"泛动词"**：`再试一次` 这个词本身在可重试类里也**不该作为首选**。

理由：`再试一次` 只说"再来"，不说"再来会发生什么"。玩家真正想知道的是"我刚才那一下算不算数、我的战绩有没有丢"。所以可重试类一律用**具体动词**：读数据 →「再读一次」；榜单 →「刷新榜单」；断网恢复 →「重新载入」。三个动词对应三种不同的"再来"，泛词只对应"我也说不清"。

## ③ 数字三档层级表

### ③-a 三档

数字的档位**不是字号档，是"这屏让你先看哪个数"的档**。所以一条屏只允许一个 T1。

| 档位 | 用途 | 字号（设计 px） | 字重 | 颜色 token | 一个真实用例 |
|---|---|---|---|---|---|
| **T1 大字报** | 一屏的结论，**一屏至多 1 个**。只在"这局的答案 / 我的总账"这种位置上出现 | **88** | 800 | 随语义：`--up-red` / `--down-green` / `--warm-white` | 战绩页累计净胜 `#rp-net`（`.rp-sum-value` 88px/800，`records.css:150-157`） |
| **T2 正文** | 一组并列的关键数值（2–4 个），或列表行内的主数值 | 主档 **48**<br>密排 **32**（列表行内 / 同排 ≥3 个） | 800 | 语义色同上；非胜负数值用 `--warm-white` | 48：胜/负/平三卡 `#rp-wins`（`.rp-gnum` 48px/800，`records.css:217-222`）<br>32：结算行净胜（`.settle-net` 32px/800，`style.css:3175`）、榜单行净值 `.rank-net` |
| **T3 辅助** | 场次、胜率、名次、x/N、时间、"共 N 场"，以及**所有单位** | **24** | 500–600 | `--gray-aux`（说明性）/ `--text-secondary`（浅底上） | 列表口径 `#rp-list-count`「共 12 场 · 列表近 20 场」（`.rp-list-count` 24px/`--gray-aux`，`records.css:369`）；成就 `#ach-entry-num`「3/26」 |

**密度开关只有一个**：同样属于 T2 时，**独占一行 → 48；列表行内或同排 ≥3 个 → 32**。除此之外不许调号。

### ③-b 数字与单位的比例关系（三条）

1. **单位永远比它所在档的数字小两档**，并降一档颜色：88 的数字配 **28** 的单位（`.rp-unit` 28px/700 `opacity .72`）；48 的数字配 **20** 的单位（`.rp-best-v i` 20px/600 `opacity .6`）；24 的辅助数字**不配单位**（"12 场"里"场"与数字同号 24——因为它读起来是一个词，不是"数 + 量"）。
2. **单位不许比数字更大、不许同号、不许同色**。单位一旦抢眼，玩家会先读单位再读数，等于把一句话读反。
3. **分母弱化**：`x/N` 里的 N 与数字同号同字重，但 `opacity .6`。理由是当分母是固定值（26 个成就）时，它是背景信息。

### ③-c 一条屏内"不得出现第四档"的具体做法

现在战绩页出现了 **88 / 48 / 40 / 32 / 28 / 24** 六个数字字号——这已经不是三档，是六个节拍器。规范的落法：

| 现状 | 归到 | 为什么 |
|---|---|---|
| `.rp-sum-value` 88 | T1 | 它是这屏唯一的结论，本来就是对的 |
| `.rp-gnum` 48 | T2 主档 | 三卡并列但各占整行宽度，48 撑得住 |
| `.rp-best-v` **40** → **32** | T2 密排 | 纪录条是"回看"信息，弱一档是对的；而且它是三列并列，正好符合"同排 ≥3 → 32" |
| `.settle-net` 32 | T2 密排 | 结算列表行内，正确 |
| `.rp-unit` 28 | 单位（不占档） | 见 ③-b |
| `.rp-list-count` 24 | T3 | 正确 |
| `.rank-no`（名次/奖牌） | T3 | **名次是辅助信息**：玩家看榜先看名字和自己的净值，名次是定位用的。今天它靠字号+emoji 抢眼，靠 emoji 就够认了 |

**硬约束**：同一屏内，**数字元素的 `font-size` 去重后 ≤ 3**（单位元素不计入，因为单位必须严格小于其数字）。这条可以直接断言，见 ⑥-9。

### ③-d 两条禁止

- **禁止用字重冒充档位**。`32px/900` 不是"比 48px/800 更重要"，它只是"更粗的 32"。重要性靠档位和位置表达，不靠加粗。
- **禁止 T1 出现第二个**。两个都在喊的数字，等于都没在喊。若真有两个结论（如"本局净胜"和"累计净胜"），把本局那个升 T1、累计的降 T2 并加标签「累计」。

## ④ 明确不做

| # | 不做 | 为什么不做 |
|---|---|---|
| 1 | **不做骨架屏，尤其不做逐格闪动** | 这游戏的数据是本地优先（`Records.stats()` 走 `localStorage`），加载常在 200ms 内完成。闪一下比不闪更烦，而且骨架屏的"格子"和"有数据"的卡片长得像——**四态分离立刻破功**。加载态的正确形态是"零按钮 + 一个环 + 一句 7 个字"，不是"假装马上就有内容" |
| 2 | **不做自动重试 / 退避轮询** | 战绩和榜单是"打开就要一眼看完"的页，不是实时监控。弱网下 8 秒超时 × 3 次自动重试 = 转圈 24 秒，玩家会以为卡死。给一个按钮，比在后台偷偷重试诚实——**要不要再来，是玩家的事** |
| 3 | **不给玩家看错误码**（`E1023` 之类） | 玩家拿它没用；客服也不需要——`ErrorReport.capture` 已经带了 kind / message / source / stack，还有去重。把机器标识印到屏幕上，只是把工程的债转成玩家的困惑 |
| 4 | **不做加载百分比 / 假进度条** | 没有可信的总量，编一个进度等于撒谎；而且"87% 卡住不动"比"一直转"更让人焦虑。要处理"慢"只有一个办法：**超过 1 秒把副文案换成「比平时慢一点，再等等」**，说人话 |
| 5 | **不做失败态的全屏红 / 红色遮罩** | 失败多半只是"少了一块数据"，不是"游戏坏了"。而且 `--up-red` 在这游戏里是**涨红＝赢**（`.rp-sum.up`、`.settle-net` 都用它），把红色挪用给"错误"会直接污染胜负语义。失败态用深底 + 金描边，和 `.toast.warn` 同一手法 |
| 6 | **不做"离线也能玩"的文案承诺** | 人机局与联机在同一入口。写"离线也能玩"会让人点了房间再失败第二次。离线态只说**它实际给的**：「先把这台设备上的记录给你看」，一个字不多 |
| 7 | **不给四态加音效** | 加载没有声音是正常的；给"正在读"配一声，等于每次翻页响一下。`Sfx.play('error')` 只在"玩家主动点、被拦下"时保留（`blockedOffline()` 现有行为），其余一律静音 |
| 8 | **不新增插画**（四种态四项） | 插画是稀缺资源，全是手写内联 SVG。四个插画＝四个"这游戏在给你图画"的时刻，会把插画的价值摊薄。**空态是唯一该有插画的地方**（它要安慰一个一场没打的新玩家）。加载/失败/离线靠**形态**区分：零按钮 / 两按钮 / 左对齐横条 |

### ⑤-b 必须新建（且只许新建这些）

1. `#records-loading`（`class="rp-state rp-state--loading hidden"`）——44px 金环 + 标题。
2. `#records-fail`（`class="rp-state rp-state--fail hidden"`）——标题 + 副文案 + 主/次两个按钮。
3. `#records-offline`（`class="rp-state rp-state--offline hidden"`）——**一个块、两种形态**（strip / panel），靠 `.is-strip` / `.is-panel` 切换，**不许建两个块**：它们是同一件事，两块就是两套文案，迟早不一致。
4. `#records-source-retry`——失败降级时塞进 `#records-source` **同一行右侧**的 ghost 小按钮（不新起一行，页脚高度不变）。

7. JS 里两样东西：
   - `STATE_TEXT` —— 一个对象字面量，装下 ②-b 的全部文案字符串。**不许把文案散在 if 分支里**（现状就是散在 `renderRecords()` 里，见 §0）。
   - `recordsStateOf(...)` —— 纯函数，见 ①-c。

### ⑤-c 同一屏里怎么切（互斥组与非互斥项）

**互斥组**（同一时刻**只有一个块不带 `.hidden`**）：

```
#records-loading  |  #records-fail  |  #records-empty  |  #records-scroll(+#records-data)
```

配套：`#records-foot` 的显隐跟着"是否有内容"走（沿用现状：空态不显示页脚）。

**非互斥项**：`#records-offline`。它**允许叠加在任何态之上**：

- `data` 态 + 离线 → 显示内容 + `#records-offline.is-strip`（贴在 `#records-foot` 上方）。
- `empty` 态 + 离线（本机确实 0 局且未登录语境）→ 显示空态 + `is-strip`。
- `loading`/`fail` 被离线覆盖时（优先级高）→ 直接判 `offline`，用 `is-panel`。
- 本机 0 局 + 登录中 + 离线 → `offline` 的 `is-panel` 独占（因为"本机没有"不能推出"你账号没有"）。

> 这一条最容易错：**如果把离线塞进互斥组，那么"离线 + 有本机数据"时会整页空**——玩家明明能看自己的战绩，却被告知没网。本设计里离线态**永不隐藏内容**，这也是我反对"把离线做成第四个满屏态"的理由。

**切换的唯一执行者**：一个 `setRecordsState(name)`。禁止各处零散 `classList.toggle('hidden', …)`——现状 `renderRecords()` 里散着四处 toggle（`#records-scroll` / `#records-data` / `#records-empty` / `#records-foot`），加第四态那天必定漏一处，漏一处的表现就是"两个态同屏叠着"。

### ⑤-d 过渡与"防闪"

- **切换用 opacity，禁用位移**。`--dur-2 var(--ease-std)` 消失、`--dur-3 var(--ease-emph)` 出现。位移会让"四个块"看起来在互相推开，而它们其实是同一个位置的四种说法。
- **加载态的显示门槛：250ms**。0–250ms 内**什么都不显示**（只有屏背景），不许显示空态。理由：本地读常 200ms 内完成，先闪空态再切有数据是**最坏的闪**（它闪的是错的结论）。这同时呼应已有的 `probe-first-paint.js`——它守的就是"登录态未定时不许闪出错误的那一屏"。
  - 落到代码是一行常量 `STATE_DELAY_MS = 250`，不是魔法数字。
  - 代价（接受）：250ms 内没有反馈。可接受，因为屏切换本身有入场动画覆盖这段。
- **加载态"慢"的升级**：>1000ms 时把副文案换成「比平时慢一点，再等等」（仍 ≤14 字，仍零按钮）。**不加进度条**（见 ④-4）。

### ⑤-e 无障碍与交互

- 每个态容器：`role="status"`。`loading` / `offline` 用 `aria-live="polite"`；`fail` 用 `aria-live="assertive"`（它是坏消息，必须被读出来）。
- 加载环 `aria-hidden="true"`，标题文字承担语义（屏幕阅读器念"正在读取战绩…"就够了，不需要念"进度圈"）。
- 四态里**所有按钮必须 `type="button"`**（防将来被包进 form 时误提交）。
- 「重新载入」「再读一次」这类按钮的可点区域 **≥ 88 设计 px 高**（沿用 `.undo-act` 的判据：点不中等于没有这个功能）。

## ⑥ 自查点（可机检）

> 每条都写成**能自动化断言**的形式。凡是我只能用"看起来更好"来说明的，都不该出现在这张表里。

1. **加载态不许搭空态的便车**：`#records-loading` 不带 `.hidden` 时，`#records-empty` 必须带 `.hidden` **或不存在**。
   反例（现状）：只把 `#records-empty-title` 的文字换成「正在读取战绩…」——**这不算加载态**，这是空态在撒谎。
2. **互斥组同时可见数 ≤ 1**：`document.querySelectorAll('#records-loading:not(.hidden), #records-fail:not(.hidden), #records-empty:not(.hidden), #records-scroll:not(.hidden)').length <= 1`。`#records-offline` 不在此列（它是非互斥项）。
3. **按钮数量是签名**：加载态容器内 `querySelectorAll('button').length === 0`；离线态 `=== 1`；失败态 `>= 2`；空态 `=== 1`。（任一条不成立，①-b 的自证矩阵就失效）
4. **四个态标题互不相同**：取四态容器内第一个标题元素（`.rp-empty-title` / `.rp-state__title`）的 `textContent.trim()`，去重后长度必须 `=== 4`。
5. **文案长度**：标题 `length <= 14`，副文案 `length <= 26`（空的副文案成立）。
6. **对齐是结构差异，不是口味**：离线态块的 computed `text-align === 'left'`；空/加载/失败态 `=== 'center'`。
   这条专治"为了好看把离线改成居中"——那样它就退化成"只换了文案的第二个空态"。
7. **禁用词**：`document.body.innerText` 不匹配 `/操作失败|请稍后重试|网络异常|请求失败|系统繁忙/`。
8. **「再试一次」只准出现在可重试容器里**：全站匹配 `/再试一次/` 的元素，其最近的 `[data-err-class]` 祖先必须为 `retryable`；否则 0 个。
9. **数字档位 ≤ 3**：在 records / settle / rank 三屏分别取所有"只含数字与符号"的元素 computed `font-size`，去重后数量 `<= 3`；且每个单位元素（`[data-role="unit"]`，现有 `.rp-unit` / `.rp-best-v i`）的字号必须**严格小于**其同级数字。
10. **静默 = 页面不变**：注入一次云端档案读取失败 → `ErrorReport.capture` 的调用次数 `>= 1`；同时断言 `#records-scroll` 的 `innerText` 与失败前**逐字相等**（页脚那一行除外）。这是"静默"的**唯一可执行定义**。
11. **榜单失败不许复用空态**：`#rank-fail` 与 `#rank-empty` 必须是两个不同元素；静态检查 `renderRank()` 的 `failed` 分支中不得出现对 `#rank-empty` 的写入。
12. **离线会自己走开**：`navigator.onLine === false`（模拟）时 `#records-offline` 与 `#net-banner` 都不带 `.hidden`；派发一次 `window 'online'` 事件后 **500ms 内**两者都带 `.hidden`。
