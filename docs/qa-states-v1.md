## 1. 规格裁定（施工前必须先认这三条，否则判据会互相打架）

### 1.1 裁定一：不是「四态」，是「四态 + 正常态」五值

任务书说「四态（空/加载/失败/离线）互斥」。**字面执行会自相矛盾**：有数据可看的时候，四个态一个都不该出现，那就不满足「恰有一个」。

我的裁定：状态域是**五值**，四态是其中「非正常」的那四个。

| 状态值 | 含义 | 载体（白名单，一一映射） |
|---|---|---|
| `data` | 有数据正常展示 | `C_data` = `#records-scroll` + `#records-data`（**视为同一载体，只数一次**） |
| `empty` | 确实一条记录都没有 | `C_empty` = `#records-empty` |
| `loading` | 该有数据、还没回来 | `C_loading` = `#records-loading`（**新建**） |
| `fail` | 拉取失败，结果未知 | `C_fail` = `#records-fail`（**新建**） |
| `offline` | 断网，请求不可能成功 | `C_offline` = `#net-banner`（复用 index.html:242）+ `#screen-records` 上的状态值 |

**互斥断言的对象是这 5 个载体，不是 DOM 里所有元素。** 现有实现里 `#records-scroll` 与 `#records-data` 在数据态**同时可见是正确的**（`recordsView.js:310-311` 两行 toggle 同一个 `hasData`）。若把它们当成两个载体去数「恰有一个」，正确的实现也会红 —— 这是我在写判据时先撞到的误伤，记在这里（详见 S1）。

### 1.2 裁定二：离线是**抢占**，但允许一处叠加豁免

- 离线时**不得**进入 `loading`：加载依赖网络，断网时「加载中」是骗人的。抢占用 S9 断言。
- 离线且有本机数据时：`data` + `#net-banner` **同时可见是允许的**，这是本组判据里**唯一**的双显豁免，写死在判据里，别处不得再开口子。
- 离线且无数据：状态值必须是 `offline`，**不得**是 `fail`。因为「失败」暗示「再试一次可能成功」，而玩家此刻该做的事是「连网」，不是「重试」。

### 1.3 裁定三：错误三级分类的定义

| 级别 | 名字 | 判据口径 | 项目里的真实例子（独立入口，不是我为判据造的例子） |
|---|---|---|---|
| **L1** | 可恢复 | 有明确动作，且该动作**真的会重发** | `/me/records` 500 或超时（`recordsView.js:257` `loadCloudRecords`） |
| **L2** | 不可恢复 / 终态 | **禁用词表**命中数 = 0，且只给一条正确出路 | `authFatalMsg` 覆盖的四类：未登录 / 登录已失效 / 账号不存在 / 已被停用（`game.js:400`） |
| **L3** | 静默 | 只上报不打扰：上报 **1** 条、可见 toast **0** 条 | 分享图 / 下载失败（`recordsView.js:1120` `reportQuietly`） |

**禁用词表（L2 口径，手写、外部定义，不从实现字符串里抄）**：

```
再试一次 │ 再试 │ 重试 │ 稍后再试 │ 稍后重试
```

**矛盾词对表（S16 用，手写）**：`{网络, 账号}`、`{网络, 版本}`、`{网络, 已在别处登录}`、`{暂无记录, 读取失败}`。

## 3. 三条最容易假绿的断言反例

### 反例① 断言「文案相等」——只改文案的错误实现也是绿的

- **错误写法**：`await page.text('#records-empty-title') === '正在读取战绩…'` 即判 loading 通过。
- **为什么它会绿**：这正是现实现的形态 —— `recordsView.js:336-351` 在 `!hasData` 分支里**只换两句文案**，布局、插画、按钮全是空态那一套（index.html:722-742）。所以「文案对上了」这件事，在「加载态与空态共用视觉壳」这个**真缺陷**存在时**依然成立**。这条断言测的是「有没有改字符串」，不是「有没有一个加载态」。
- **正确写法**：断言载体本身 —— `#records-empty` / `#records-empty-art` / `#btn-records-create` 三者 `checkVisibility()` 全 false，且 `C_loading` 可见（S3）；再加负向「加载态下页面出现数字 `0` 的实例数 = 0」。文案最多只能作为**辅助**断言，不能当主判据。

### 反例② 打桩 `navigator.onLine` / 直接调内部 API —— 测的是分支，不是行为

- **错误写法 A**：`page.evaluate("navigator.onLine = false")` 之后断言「离线提示出现」。
  它绿的原因：这只改了 `isOffline()`（`game.js:3179`）读到的那个字段，**网络其实是通的**。真实断网时 `fetch` 会 reject、WebSocket 会断、`/me/records` 会超时 —— 这些后续行为一条都没被验证。你验证了自己写的一行 if。
- **错误写法 B**：`page.evaluate("RecordsView.loadCloudRecords(true)")` 之后断言界面状态。
  它绿的原因：**玩家没有那个钩子**。这正是「24 项浏览器验收全过，用户却说上下左右不顺畅」的成因 —— 全绿与能玩之间没有关系。
- **正确写法**：用**真实条件**驱动 —— CDP `Network.emulateNetworkConditions{offline:true}`（Chromium 会**同时**置 `navigator.onLine=false`，两条路一起断），然后**只从玩家入口走**（点进战绩页、点重试）。验收脚本里出现 `evaluate` 调内部函数 = 这条用例作废。

### 反例③ 断言 `textContent` 非空 —— 「写了但看不见」是这个项目里的现成缺陷

- **错误写法**：`assert((await page.text('#records-source')).includes('读不到'))`。
- **为什么它会绿**：`recordsView.js:332` **确实**往 `#records-source` 里写了「账号数据暂时读不到，先显示这台设备上的记录」。但这个元素在 `#records-foot` 里，而 `recordsView.js:313` 在 `!hasData` 时把整个 footer 加上 `.hidden`（`style.css:190`：`display:none !important`）。**而「云端失败 + 本机也没数据」恰恰就是新玩家最常遇到的那个状态** —— 解释写得妥妥的，玩家一个字都看不到。`textContent` 不管可见性，所以这条断言在缺陷存在时**永远是绿的**。
- **正确写法**：可见文本 = 遍历 DOM + `checkVisibility()` 过滤后拼接（S7）；并加一条**专门的负向断言**：「`textContent` 非空但父链含 `.hidden` 的元素个数 = 0（针对状态类文案）」。这条负向断言的价值高于正向断言 —— 它专抓这一类「写对了位置、藏错了层级」。

## 4. 分层：每条判据落在哪一层

分层规则（先定规则，再套用，避免逐条拍脑袋）：

- **可见性与尺寸** → 只能进**真浏览器探针**（`getBoundingClientRect` / `checkVisibility` / `computedStyle` 在 node 里都没有真相）；
- **状态机与计数** → 可以进**单测**（纯函数、决策表、去重/节流逻辑）；
- **手感与文案读感** → 只能**人工实玩**（"这句话像不像在安慰我"机器判不了）；
- **网络请求计数** → **探针**（CDP 网络层），不能进单测（单测里的 `fetch` 是假的，数的是桩）。

| 判据 | 层 | 理由 |
|---|---|---|
| S1 | **探针** + 单测 | 可见性必须探针；「状态值 ⇄ 载体」的映射表可以单测（纯查表） |
| S2 | **单测** | 静态结构检查：`data-rstate` 值域、载体白名单是否与 §1.1 一致 |
| S3 | **探针** | 纯可见性 + 需要人为制造 800ms 窗口 |
| S4 | **探针** | `aria-busy` 与元素尺寸都只有浏览器里是真的 |
| S5 | **探针** | 命中区 44×44 是几何量 |
| S6 | **探针** | 计的是**网络层**请求数；单测数的是桩的调用次数，正好是要防的假绿 |
| S7 | **探针** | `checkVisibility()` 只有浏览器有 |
| S8 | **探针** | 依赖 toast 真实生命周期事件 + 真实断网 |
| S9 | **探针** | 请求增量 = 0 只能从网络层看 |
| S10 | **探针** | 点击回执是时序 + DOM 变化 |
| S11 | **单测** | 「错误码 → 级别」是纯查表，含唯一性校验 |
| S12 | **单测（分类器）+ 探针（取可见文案）** | 正则自测可单测；但被检对象必须是**可见**文案 → 抽取在探针 |
| S13 | **探针** | 可见可点控件计数 + 白名单，都是渲染结果 |
| S14 | **探针** | 复用 S6 的网络计数 |
| S15 | **探针（主）+ 单测（辅）** | 服务端日志与可见 toast 计数都在浏览器侧；去重逻辑可单测 |

| S17 | **探针** | 尺寸、遮挡、溢出 |
| S18 | **探针** | 帧序列 |
| S19 | **单测（结构断言）+ 人工（变异抽样）** | 「有没有被调用」可静态查；「改坏了会不会红」要人跑 |

## 5. 人工实玩清单（7 条，每条一句）

> 全部要求：**关掉一切、从浏览器地址栏打开、不点文件、不看 README、不用任何调试钩子**。走不通的就是走不通。

1. **读屏正常**：用手机从地址栏打开战绩页（已登录、有记录）→ 应该看到数据态，且**看不到**任何"加载中/失败"的残留。
2. **空态不撒谎**：新账号（一场没打）进战绩页 → 应该看到"还没有战绩，去开一局吧" + 创建房间按钮，且这条文案在**网络正常**时出现（不是等超时后）。
3. **加载态看得见**：弱网（地铁/限速到 2G）下进战绩页 → 应该看到明确在"读"的样子，**不应该**看到那个写着"0"的空态插画。
4. **失败态能重来**：飞行模式开 3 秒再关（或者让服务端挂掉）→ 进战绩页 → 应该有一句人话 + 一个**点得动**的"重试"；点它 → 数据应该真的回来（不是原地不动）。
5. **不可恢复态不哄人**：用一个已停用的账号进游戏 → 应该只给"回登录"一条路，**任何一个字都不许出现"再试一次"**；读完我心里应该知道"这事重试没用"。
6. **离线不靠一闪而过**：飞行模式进战绩页 → 应该有一块**一直在**的提示说没网；等那条 toast 自己消失后，提示**仍然在**；关掉飞行模式 → 提示自己消失、数据自己回来。
7. **静默失败不打扰我**：战绩页点"生成分享图"并在系统层面取消保存 → 应该**什么提示都没有**（不弹 toast），但下一局我打得下去、界面一切正常。
