# UI 质量审计：质感 · 交互 · 友好度（2026-11-07 · v133 基线）

> 视角：前端设计与 UI 系统。**只审不改**，产出为可执行的三批计划。
> 数字全部可复跑；没实测的写「未测」。
> 基线：`20261102v` / sw `v133`；CSS 7310 行（style.css 5454 / records.css 1118）。
> 本版重心按负责人要求落在**质感、交互、友好度、体验**，布局与配色只作为证据。

---

## 〇、判定

**这套 UI 已经有「语气」，但还没有「语法」。**

语气是清楚的：墨绿毡面牌桌 + 暖白纸感卡 + 金色描边，是一个有辨识度的方向，
而且作者已经为对比度做过正经决策（`--gold-ink` 的注释写着"`--gold` 在暖白底上只有 1.5:1，等于没写"）。
缺的是把这种判断变成**可复用的规则**：光从哪儿来、浮起分几层、动效多快、
同一件事的三种画法该收敛成哪一种。

对玩家的表现不是"难看"，是**"说不出的不整齐"**——每屏都还行，串起来不像一个应用。

## 二、问题（按「玩家能不能感觉到」排序）

### 2.1 质感：没有统一光源，所以"浮起"不可信

71 种 `box-shadow` 不是审美问题，是**物理问题**：现实里所有物体被同一个光源照亮，
投影方向与柔度随高度连续变化。71 个答案等于 71 个光源，大脑读不出"谁在谁上面"。

现在能观察到的三个层次（结算冠军卡 / 回放把卡 / 座位面板）各自"浮"得不一样，
于是玩家分不清**哪些是可点的、哪些是静态内容**——这是最直接的可用性损失，
比颜色不统一严重得多。

### 2.2 质感：纸卡缺"边缘"

纸感卡片靠 `--warm-white` + 阴影表达，缺少**1px 发丝描边 / 内高光**。
这是"廉价塑料卡"与"厚纸"的分水岭：有了边缘，材质才有厚度；没有边缘，再柔的影也是贴图。

### 2.3 交互：按压回执有三种，动效没有节律

先纠正一个常见误判：**按压态不是没有**（32 处 `:active`，主按钮全在）。问题是**回执不统一**：

| 写法 | 处数 |
|---|---:|
| `transform: translateY(2px)` | 5 |
| `transform: translateY(6px)` | 1 |
| `transform: scale(0.94)` | 1 |
| 只变背景色（3 种不同 rgba） | 3+ |

同一个「按下」动作，有的下移 2px、有的 6px、有的缩 6%、有的只变色。
玩家手指感受到的是**三种不同的物理反馈**——这不是手感差异，是同一台机器上三套触感。

时长同理：7 档（0.1 / 0.12 / 0.15 / 0.16 / 0.22 / 0.25 / 0.4s），前四档差 20~50ms，
人眼不可辨，属于"凭感觉调"的残留。另外两点未设计：
- **可中断**：超过 200ms 的入场动画，第二次点击应该是"直达终态"而不是重播；
- **降级**：`prefers-reduced-motion` 只覆盖了 5 处，其余动画在"减少动态效果"下照旧。

### 2.4 友好度：三态里只做了一态

空态有文案（"还没有战绩，去开一局吧"），但：
- **加载态**与空态边界不清——`probe-records-cloud` 曾把"正在读取战绩…"当成空态断言而假红，
  这不是探针的错，是**界面自己没把 loading 画成一个可识别的状态**；
- **失败态**统一成"出了点问题，已经记下了"（v127 的 `reportBug`）——对玩家友好，但对"能不能重试"没有信息；
- **离线/断线**：玩家不知道为什么卡住，也不知道要不要等。

### 2.5 体验：危险动作只有"确认框"，没有"后悔"

清除记录、离开房间、删号都是不可恢复动作，现在统一用确认框。
移动端的成熟做法是**可撤销**（执行 + 5 秒 undo），确认框是桌面时代的解法：
它把"防止误触"的成本转成了"每次都要多点一下"。

### 2.6 体验：数字是主角，却没有主角的排版

这游戏的阅读对象是数字（`+15` / `-3` / `10.5` / `第 3 把`）。
等宽数字（`tabular-nums`）**已经做了 45 处**（style 30 / records 15），比预期好；
真正的缺口是**层级**：数字与标签共用同一套 33 档字号，字重也各自为政，
于是结算页的净胜、组头的「赢得 8 分」、回放行尾的 `+2` 在视觉重量上互相打架 ——
玩家一眼分不出「哪个数是我最该看的」。

### 2.7 体验：等待没有"进度感"

一局 10 把，每把之间有结算 → 报名 → 发牌；
「等人」时房主挂起最长 3 分钟（v122 `holdNext`）。这段时间**别人看到的是什么**，
决定了这 3 分钟是"等"还是"卡住"。

### 2.8 体验：首次进入没有策略引导（设计域已判为最值钱的一块，5.0 分）

规则页讲规则，不讲**怎么分牌能赢**。而这是一个 60 种分法的组合优化游戏。

## 三、三批计划

> 排序原则：**先让"质感"可信（一条光规则），再让"交互"有节律，最后补"友好度"的内容**。
> 理由：前两批是**结构性**的（一次改动，全局受益），第三批是**内容性**的（一件一件做）；
> 而内容性工作如果建在不稳定的材质上，做完还要返工。

### B1 · 一条光规则 + 纸的实现（0.5~1 人日）

| 项 | 做什么 |
|---|---|
| **光源** | 定 4 层 elevation token：`flat`（无影）/ `raised`（内容卡）/ `modal`（弹窗）/ `popover`（浮层菜单）。每层 = 一层柔影 + 一层极淡外描边。**71 → 4** |
| **纸的边缘** | 纸卡统一加 1px 内高光（`inset 0 1px 0 rgba(255,255,255,.6)`）+ 1px 收敛描边，让"厚度"来自边缘而不是阴影 |
| **毡面** | 桌面底加一层极淡径向渐变（中心略亮），零资源、不引图；只在 `#stage` 背景，不碰任何卡片 |
| **数字** | 全局 `font-variant-numeric: tabular-nums`（牌面/分数/倒计时/名次），消除跳动 |

**判据（可机检）**
1. `grep -o "box-shadow:[^;]*" pwa/css/*.css | sort -u | wc -l` **≤ 4**（不含 `none`）；
2. `pwa/test/design-tokens.test.js`：新增裸 `box-shadow` 直接红（带变异自证：塞一个进去必须红）；
3. `probe-ui-flow` 12 档 × 13 屏：无新增遮挡/溢出，`paintedRect` 判定不变；
4. 人工：结算页 / 回放 / 座位面板三处截图并排，**"谁在上"一眼可读**。

**风险**：改阴影会牵动 39 个卡片的观感 → 必须用 12 档截图对比做回归；不可逆性低（纯 CSS）。

### B2 · 交互节律（1 人日）

| 项 | 做什么 |
|---|---|
| **时长** | 7 → **3 档**：120ms（微反馈：按压/高亮）/ 200ms（状态切换：弹窗/切换屏）/ 320ms（入场：卡片浮起）。缓动统一 2 条：`standard` / `emphasized` |
| **按压** | 所有可点元素补 `:active`（缩放 0.97 + 亮度 -4%），移动端才有"按到了"的回执 |
| **可中断** | >200ms 的入场动画支持"点击直达终态"；玩家的第二次点击不是想看动画 |
| **降级** | `prefers-reduced-motion: reduce` 覆盖到**全部**动效（现在只有 5 处） |
| **焦点** | `:focus-visible` 补到 100%（emoji.css 现在是 0）；桌面档（1280×720 / 728×348）真在用 |

**判据**
1. `transition` 时长去重 **== 3**；`prefers-reduced-motion` 覆盖检查：把媒体查询里的选择器数与 `transition`/`animation` 总数比对，缺口 0；
2. 新增探针断言（`probe-ui-flow`）：**点击任一主按钮后 120ms 内必须有可见变化**（`transform`/`opacity`/`background` 任一变化），否则红；
3. `focus-visible` 覆盖：`grep -c` 在 4 个 css 文件里均 > 0，且按钮类全覆盖。

**风险**：`prefers-reduced-motion` 全量覆盖会让"降级后会不会有动画卡在半路"成为新风险 → 降级时统一 `animation: none; transition: none`，并跑 12 档。

### B3 · 友好度与体验（1.5~2 人日，可分三次发）

| 项 | 做什么 | 判据 |
|---|---|---|
| **四态** | 空 / 加载 / 失败 / 离线 各有一个**可识别的视觉**（不是同一块空白填不同文案）；加载态必须有骨架或明确的进度，不许出现"看着像空"的中间态 | 战绩页与结算页各一条断言：loading 时 `.empty` 类**不存在**；失败态带"重试"按钮且点击有效 |
| **错误分级** | 可重试（网络）/ 不可恢复（数据）/ 静默（上报用）三类，文案与动作不同；保留 v127 的"必须上报" | 三类各有独立文案 key；不可恢复类不含"再试一次" |
| **可撤销** | 清除记录 / 离开房间改「执行 + 5 秒撤销」。删号仍用确认框（不可撤销，且合规要求明确意图） | 撤销窗口内点击"撤销"能恢复；5 秒后不可恢复；探针验证一次 |
| **数字排版** | 数字 3 档（大字报 / 正文 / 辅助）+ 权重规则（净胜 > 单组得分 > 名次） | 结算页多行数字基线对齐（截图）；`tabular-nums` 全局 |
| **等待可见** | 「等人」时其他人能看到：谁在等、已等多久、还差谁（现在只有房主视角有用） | 非房主在 `holdNext` 期间能看到倒计时与原因 |
| **策略引导** | 首局结束后一行"下次可以这样分"（复用 `bestLine` 的结论，不暴露对手牌） | 只在一局结束后出现一次；不计入成就；可关闭且记住 |

**风险**：可撤销会改动作语义（清除记录不再是即时删除）→ 必须确认"撤销窗口内数据仍在"，且窗口失焦/退后台要立即提交（否则用户以为删了其实没删）。

## 四、防止回潮：把设计约束变成断言

这个项目的文化是"规则要能被机检"（`probe-ledger` / `ci-matrix` / `no-silent-catch` 都是这个路子）。
设计约束同样可以：

**新增 `pwa/test/design-tokens.test.js`**，四类断言 + 变异自证：
1. 字号取值集合 == 8 档（B1 之后收紧；当前 33 档先白名单，只准减不准增）；
2. `box-shadow` 去重 ≤ 4；
3. 裸 hex 只允许出现在 `:root` 定义处；其余必须走 `var(--*)`；
4. `rgba()` 只允许来自 4 个 overlay token（遮罩 / 描边 / 内高光 / 阴影色）。

**变异自证**（这条是它能不能算数的唯一理由）：往 CSS 里塞一个 `#123456` 和一个第 5 种阴影，
测试必须红；删掉再绿。

## 五、明确不做（都是有理由的"不"）

| 不做 | 为什么 |
|---|---|
| **换整体配色 / 换风格** | 墨绿毡面 + 暖白纸 + 金 是有辨识度的方向，且对比度已经做过取舍（`--gold-ink`）。换掉等于把已有的判断清零 |
| **引入 Web 中文字体** | 一个可用的中文子集至少 1~2MB，PWA 首屏与离线缓存都吃不消。现有系统字体栈是正确选择 |
| **动 stage 缩放体系** | 12 档 × 13 屏全靠它，动它等于重做适配 |
| **追视觉流行（玻璃拟态 / 大圆角 / 渐变炫光）** | 这游戏的气质是"牌桌"，不是"设置页"。质感来自**一致的光与边**，不来自效果堆叠 |
| **给所有元素加动效** | 动效的作用是**解释状态变化**，不是装饰。加在没变化的地方只会让界面变慢 |

## 六、取证限制

- 未做真人可用性测试；"玩家感觉到什么"部分是**基于代码与既有截图的推断**。
- 未在真机上验证"按压态"手感（`:active` 在 iOS Safari 需要 `touch-action` 配合，属实施期风险）。
- 未测首屏体积影响（B1 的渐变与描边是纯 CSS，预期 +0 请求；实际 diff 需在实施后量）。
- 未核 emoji.css 的 0 处 `focus-visible` 是否因为该文件只画表情格子、按钮在别处 —— 实施时先确认，避免"补一个不存在的需求"。
