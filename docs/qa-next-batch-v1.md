**AC-NB-07 专段（导航中被结账）**

- 可机检形式：记广播到达时刻 `t0`，**N = 250 ms** 内 `#undo-bar` 必须满足二者之一：① `classList.contains('hidden') === true`；② `#undo-act.disabled === true`，或条子的 `aria-live` 状态改为「不可撤销」文案且点击不再调用 `onUndo`。同时同屏 `#room-hint` / 结算数字必须已反映「已结算」。
- **N 的取值来源（独立复算，不引用被测常量）**：与 `probe-numbers.js:395-407` 的换屏动画 settle 等待（0.3 s）、`probe-ui-flow.js` 的 13 屏流程同量级；**N 必须严格小于撤销窗口 5000 ms 的 1/10**（250/5000 = 5%，手算），否则广播窗口覆盖整个撤销期，判据失去区分力。N 写死为断言常量，实装时若调整须同步改规格与 CI。
- **只能用真浏览器测的部分**：广播的**真实到达时序**、WebSocket 消息与 `showScreen` / `flush('navigate')` 的**先后**、玩家在 `t0` 那一刻是否正看得见这条「可撤销」条子 —— 这些是渲染 / 时序事实，静态正则与 Node 单测都测不出。必须扩 `scripts/probe-undo.js`（CI `test.yml:255-258` 已有该 step），注入广播并**录帧**；不许另起一个不挂 CI 的探针。
- 负向：构造「广播已到、条子仍可撤销」的变异，AC-NB-07 的命中数必须 **≥ 1**（即该断言必须能红，见 §三 M2）。
- 真人路径要求见 §四（冷启动、不点文件、不看 README、不用调试钩子，走到第一个决策点）。

## 二、三条「最容易假绿」的反例

### 反例 1 · 只看「调用了 `undoBar.show`」不核 `leaveRoom` 调用次数

- **看起来通过**：接线守卫 `ok(/undoBar\.show\(/.test(gameJs))` 绿，`probe-undo.js` 也绿，撤销条确实出现在屏幕上、能点、能倒数。
- **为什么其实不该判绿**：`show()` 只是把待办挂上，**`onCommit` 有没有真的接到 `RoomStore.leaveRoom`** 是另一回事。接线断了（例如 `onCommit` 写了 `cleanupRoom()` 但漏了 `leaveRoom`）时，条子照常显示、撤销照常「成功」、0 次 `leaveRoom` 照样成立 —— 全绿；而玩家以为自己离开了房间，服务端里他还在。这是「事实为真、因果错配」型：重跑一定通过，但结论是错的（同上一轮审计 D18 的形状）。也可类比「24 项浏览器验收全过，但那些验收全部通过调试钩子主动调 API —— 玩家没有那个钩子」。
- **正确处置**：AC-NB-04 / **AC-NB-05 成对**（撤销后 0 次、到点后 1 次）+ AC-NB-09 接线守卫核到调用点，三者同时绿才算；变异清单放一条「把 `onCommit` 里的 `leaveRoom` 删掉」→ 必须红（§三 M1）。**单独看 0 次不足以判绿。**

### 反例 2 · 按文字内容采集数字元素（emoji 名次 / 单位 span 看不见）

- **看起来通过**：`COLLECT` 的 `ownText()` + `NUM` 正则统计出的数字全集 ⊆ 阶梯，「T1 只有一个」「单位严格小于数字」全绿；320 档跑完也「全绿」。
- **为什么其实不该判绿**：v138 实测变异给 `:nth-child(-n+3) .rank-no { 32px }` 单独调字号，**top3 名次是 emoji 奖牌（🥇🥈🥉）、没有数字文本**，按文本采集的探针**完全看不见**，加了覆盖仍然全绿（`probe-numbers.js:486-489`、`build-numbers-v1.md:16` 记「第 4 条变异第一次没红，逼出了逐行量 emoji 名次格子」）。同理 `.rp-unit`（「分」）与 `#rp-net` 的几何关系、被裁掉的字符，都不是文本能表达的；而 §3.2 欠的恰恰是**几何溢出**，与文本无关。
- **正确处置**：AC-NB-19 用独立 `collectGeometry()` 按 `querySelector` **量格子**（`getBoundingClientRect` / `scrollWidth` vs `clientWidth` / 相邻矩形交集），不读 `textContent`、不复用 `NUM`；保留 `probe-numbers.js:490-507` 已有的「逐行量」口径作对照且 320 档也要跑（AC-NB-21）。

### 反例 3 · 断言写 `== Config.MAX` 之类引用被测常量

- **看起来通过**：`ok(cfg.duration === DEFAULT_MS)`（取自 `undoBar.create()` 内部）、`ok(seconds === SM.HOLD_TTL_MS/1000)`、`ok(fontSize === T1)`（`probe-numbers.js:51` 自己的常量）、`ok(netRect.right <= container.clientWidth)`（容器宽度由被测 CSS 的 `var(--num-1)` 撑出来）、`ok(room.players.length === CONFIG.MAX_PLAYERS)`。这些断言**永远绿** —— 被测代码改了，期望值跟着一起改。
- **为什么其实不该判绿**：期望值与被测实现同源，判据失去证伪能力。`probe-numbers.js:25-26` 自己把「查 `#rp-net` 这类 id 的绝对字号」列为假绿反例②；`build-numbers-v1.md` N1 也说明判「在不在梯子上」而不是「钉住实现细节」。更糟的是它常与「负向计数缺失」同时出现：改坏实现后，0 次违规仍然是 0 次。
- **正确处置**：期望值一律来自规格表 / 手算 / 独立实现 —— `5000` 与 `180000` 写死（来源 `undoBar.js:31` 契约与 `stateMachine.js:1256` 的 `3*60*1000` **手算**，作为规格引文而非运行时读取）、88/48/32/24/28/20 写死为 §3.1 规格表、10px gap 与 1px 容差写死；运行时**不得 `require` 被测模块取期望值**。每条配一条能红的变异（§三）。

> 三条分别对应「接线断了照样绿」「采集器先天性盲区」「期望值同源」，互不替代；别合并成一句「多写断言」。

### 真人路径（硬性，缺一不可）

- 必须有**一项「从冷启动、不做任何额外操作」的真人路径**：关掉一切、从浏览器地址栏打开、不点文件、不看 README、不用任何调试钩子，走到**第一个决策点**（首局结束 → 看到一行策略引导 / 看到「等人」提示 / 点「离开房间」看到撤销条）。**只走调试钩子 / 注入式脚本的验收一律不算数。**
- **三条手感判据在本批的落地**：
  - **操作响应**：点「撤销」到条子消失的帧数（真浏览器可复跑断言）+ **真人试玩录屏**（机器测不出「顺不跟手」，只测帧数不算）。

### 「写了没接进执行链的守卫等于没有守卫」的核法

1. **核退出码**：本地 `node …; echo $?` —— 必要但不充分。

### 异议 1 · 反对 ③ 复用 `lxw_guide_seen_v1` 当「只出现一次」的标记

- **反对对象**：`PLAN.md:405` 的「首局后一行策略引导」若按「沿用现有引导已读标记」落地。
- **理由（只读复算）**：`storage.js:70` `GUIDE_SEEN: 'lxw_guide_seen_v1'` 是**设备级** localStorage，且已被 `game.js:4679-4684`「首次进首页自动弹一次的分步规则弹窗」占用，`closeGuide()`（`:4533`）在**关闭规则弹窗**时就写入 `'1'`。复用后：① 看过规则弹窗但**还没打完首局**的人，策略引导永远不出现；② 清了缓存但**打过首局**的人，反而被再提示一次；③ 两种「一次」的语义（看过规则 vs 打完首局）被混成一个 key，判据无法区分「按人 / 按设备」。
