## 一、结论先行：成熟吗？优秀吗？

### 1.1 一句话判定

> **成熟：是。** 可以直接拉朋友玩，不崩、不丢数据、不泄漏别家手牌、负分也念得清。
>
> **优秀：不是。** 差的不是功能，是**「让玩家看见自己决策质量」**的那一层——
> 系统已经算得出答案，却从来没给玩家看过一眼。

### 1.8 v134：从「能玩」转向「像同一个东西」

前四个版本都在修"算得对不对"，v134 换了一个问法：**这一屏和上一屏像同一个应用吗？**
量出来的答案是"不像"——113 条阴影、83 种写法，等于 83 个光源；而现实里物体被同一光照亮，
投影应随高度连续变化。83 个答案让玩家读不出"谁在谁上面"。

做法与结果见 `ui-audit-2026-11-07.md` 的「B1 实施记录」。一句话：**3 档高度 + 纸的边缘**，
手写外投影清零，并把这个约束变成了 27 项断言。

这一轮最值得记的不是样式，是**两个只有跑起来才看得见的 bug**：
`--elev-1` 自引用（浏览器直接丢弃整条声明，元素完全没有阴影，源码里却"看着有写"）、
分类器被 `rgba()` 里的逗号切碎（真投影漏放 → 守卫假绿）。
两条都印证了同一件事：**断言写完之后，必须问"它凭什么红"**。

### 1.9 v135：把"手感"变成可以机检的东西

B1 统一了光，B2 统一了**时间**：22 条 transition 用了 9 种时长、5 种缓动。
改完之后只剩三档（120 / 200 / 320ms）与两条缓动，手写时长清零。

这一轮真正有价值的不是那两个数字，是**三处判断被实测推翻**：

| 审计原判断 | 实测 |
|---|---|
| 「`prefers-reduced-motion` 只有 5 处，覆盖不全」 | **错**。5 处里有一处是 `*` 全局兜底，覆盖本来就是 100%。数块数 ≠ 数覆盖 |
| 「按压回执有三种，要统一」 | **反了**。三种手势对应三种物体，是语法不是混乱；该统一的只有时长 |
| 「>200ms 的入场要支持可中断」 | **不必要**。入场压到 ≤320ms 后，"来不及等"这个问题本身消失了 |

还有两个只有浏览器才看得见的坑：`:where()` 写焦点兜底会被 `input { outline: none }` 反盖（权重 0），
`var(--dur-9)` 写错名字会让**整条 transition 作废**、所有按压变成"瞬间完成"而页面毫无异样。
前者改成「元素 + 伪类」权重 (0,1,1)，后者加了引用完整性断言。

守卫：`motion-tokens.test.js` 32 项 + `probe-motion.js` 16 项真浏览器（含"按下 60ms 内必有可见变化"）。

### 1.10 v136：给破坏性动作留一条退路

UI 审计里 B3 的第一条不是"更好看"，是**后悔权**：清除战绩是全站唯一不可恢复的玩家动作，
点错一次几十场记录没了，而它原来的保护只有一层确认框 ——
确认框防的是"手滑点错按钮"，防不了"我以为清的是这台设备、其实连云端一起清了"。

实现上有一处**故意偏离设计稿**：设计写「执行 + 5 秒撤销」，做成了「5 秒后执行，期间可撤销」。
因为云端 `resetMyStats` 没有逆操作，所谓"执行后撤销"只能是本机假装恢复，
而排行榜上已经空了 —— 那种"撤销成功"比不提供撤销更坏。

这一轮最值得记的是两个"看起来对、其实错"的地方：
1. **计时器清理读了自己刚刚置空的变量**：`undo()` 里先把 `pend = null` 再调 `clearTimer()`，
   而后者读的是 `pend` —— 计时器从来没被清掉。表现不是"多跑一个空回调"，
   而是**下一件事被提前执行**（野计时器到点时拿到的是新的 pend）。
   单测里那条"撤销后旧计时器不能把下一件事提前结账"就是为它写的。
2. **接线断了不会报错**：组件有一条"拿不到就退回立刻清除"的兜底，
   于是忘传依赖、DOM 换 id 都表现为"功能静悄悄地没了、数据照删"，而所有单测全绿。
   所以另开了一个 `undo-wiring.test.js` 专门守接线。

### 1.11 v137：把"看着像坏了"从"真的坏了"里分出来

这一批的起点是一句很具体的话：**全站只有一套骨架在兼职当"所有状态"**。
加载时玩家看到的是「正在读取战绩…」+ 一张写着 0 的卡片 + 一个可点的「创建房间」——
它既在撒谎（还没读到就说没有），又埋了个竞态（点进建房，请求回来又把页面重画一次）。

分工第一次走全：设计出规格、QA 独立出判据、制作人裁定后出施工单、主程序施工、
制作人**逐张看图**复核。**三轮才收**，而且后两轮修的全部是"施工者自测全绿但图上不对"的东西：

| 复核发现 | 为什么所有守卫都放过了它 |
|---|---|
| 离线时页脚还挂着「再读一次」 | 断言只查"失败态有重试"，没查"离线时不该邀请注定失败的动作" |
| 加载/离线时右上角写 `0/35` | 用未知冒充零；没人断言这个数字 |
| 离线的 panel 形态说"给你看本机记录"，而这一支恰恰 0 局 | 文案断言只比对了 strip 那句 |
| 顶部横幅压住页标题 | 布局断言只量"主控件 vs 页脚"，fixed 全站层不在统计里 |

最有价值的一条不是修了什么，是**"不藏内容"这条靠自觉**：`offlineForm()` 写对了就没事，
写错了没有任何东西会红。补断言时它立刻逼出一个真 bug —— `base` 传的是 `loading`，
而离线时 `loading` 恒 false，于是「本机 0 局 + 登录中 + 离线」会露出空态那张 0 分插画。
真相是"没问过账号"，不是"账号是空的"。

这一批也第一次出现**我改判上游文档**：panel 允许有自己的副文案（不能因为"一个块两形态共用一句"
这条美学规则说假话）；战绩页可见时顶部横幅让位（该屏已有页面级离线态，两句话不许重复）。
两条都写进施工单并标注"下一批要让设计回改"——**改判要留痕，不然下一个人按旧文档复核会判我们不合格**。

### 1.12 v138：断言看不见的那一类元素

「光」「动」收完之后剩下最多的一类没有标尺 —— **数**。设计文档写「战绩页出现了六个数字字号，
这不是三档，是六个节拍器」。到真浏览器里量了三个屏，比那句话更具体，也更难看：

- 战绩 **88 / 48 / 40 / 32**：40 用在两处（纪录条 + 列表行净值），是同一个没进规范的"第四档"；
- 排行 **40 / 28**：两个都不在梯子上；
- 成就 **68 / 34 / 30 / 24**：`.ach-count b` 基础 84，`max-width:420` 压到 68，横屏压到 62。
  舞台已经按屏宽 `scale` 过一遍了，再缩一次就是**双重缩小** —— 结果是 **390（主力机型）
  比 430 的字还小**。这一条不是审美问题，是我们自己反复写过的那类 bug（"用未知冒充零"
  的同族：用一次缩放冒充另一次）。

**判据换了，因为规范自己打架**：设计写「一屏 ≤3 档」，但它的映射表算出来就是四档
（净胜 88 + 三卡 48 + 纪录条 32 + 场次 24）。改成**阶梯封闭**：数值只能 ∈ {88,48,32,24}，
单位 ∈ {28,20}。理由是这六个值的共同点不是"多了"，是**不在梯子上** ——
`40` 是"比 48 小一点"、`34` 是"比 32 大一点"、`68` 是"小屏再缩一点"，每一个都合理，
合起来就是没有标尺。判"在不在梯子上"挡得住未来的第五个，判"几个"挡不住。

**这一轮最值钱的发现，是一条断言没红**：给 top3 名次单独加 `font-size: 32px`，
探针**全绿**。因为 top3 的名次是奖牌 emoji（🥇🥈🥉）而不是数字 —— 按"文字像数字"采集的探针
根本看不见这个元素。补了「逐行量 `.rank-no` 格子，不看内容」之后才红。

这和 v136 那个「接线断了不报错」是同一类：**守卫不是写错了，是它看不见那一类东西**。
区别是上一轮靠人工看代码发现，这一轮靠变异自证逼出来 ——
**变异自证的价值不在"证明断言有效"，在"证明断言的范围够不够宽"**。

另外顺带修掉一个跨朝向的真缺陷：结算页冠军净胜竖屏 48、横屏 40（同一个冠军在更宽的屏上变小），
和它同排的 `settle-name/settle-score/settle-net` 三个选择器被写在一条规则里一起压到 28 ——
名字是文字可以压，**数字跟着压就把净胜压成了"单位"那么大**。

## 二、四个域各自怎么说

### 2.1 设计域（创意总监）：形状是「两头高、中间塌」

5 维分数 7 / 5.5 / 5 / 7 / 6 —— **机制层（规则完备、重玩价值）都到 7，塌的是「机制」与「玩家」之间的三座桥**（数值平衡、上手友好、社交粘性）。

原文判定：

> 这个游戏把玩家当成**规则执行者**，而不是**决策者**。
> 100% 的工程预算花在「别让规则出错」，**0% 花在「让玩家看见自己的决策质量」**上。
> 一个 60 种分法的组合优化游戏，如果不告诉玩家他的分法值几分，那 60 种分法在玩家眼里就只有 1 种：**把牌塞满、点提交。**

### 2.2 工程域（主程序）：实际水位高于第一印象

> 这是一个「注释与测试投入远超同类一人项目」的代码库，工程质量的实际水位**高于代码形态给人的第一印象**。
> 真正的结构性欠账只有三笔：平台存储未收口、`game.js` 的 708 行事件容器、房间态无持久化。
> **这三笔都不是「写坏了」，而是「迭代到 v108 后规模超过了当初的形态」。**

### 2.3 质量域（质量监管）：「单测纪律罕见地好、UI 门禁罕见地缺」

> 109 文件 / 2720 静态断言调用点 / 21,722 行测试对 25,532 行源码（0.85:1），14 个域无空档。
> **但 45 个 `scripts/*.js`（37 探针 + journey + e2e-score）一个都不在 CI**，
> 而 v108 已实证「4463 条断言全绿 + CI 全绿，真浏览器里所有弹窗全哑」。
> 短板不在写得差，**在于最贵的那层测试不在执行链里**。

## 三、四个域交叉验证出来的三件事

四份报告独立写完后对照，有三条是**多个域同时指向**的，可信度最高：

| # | 结论 | 谁指出的 | 为什么可信 |
|---|---|---|---|

### 5.1 读旧 review 的四个坑

1. **「历史快照」不等于现状。** 每份档案头部都写了覆盖到哪一版、被谁覆盖。标了快照的，结论可能已被后来版本推翻。
2. **BACKLOG 的条数不能 grep。** 有五种关闭写法（`**已完成**` / `**已修**` / `**已做**` / `**v79 已修**` / 仅标题变化），grep 出来一定是错的。**按编号逐条读**才准。
3. **标题可能比内容旧。** 例：`N6` 标题写着「v89 计划中」，实际 v89/v90/v91 已全部上线。**按标题读会把已完成项当待办**。
4. **「测试全绿」不等于「能用」。** v108 的实证：4463 条断言全绿 + CI 全绿，真浏览器里所有弹窗全哑——因为 bug 在「模块接线」这一层，旧断言查的是「源码里有没有这段字符串」。
