## 0. 这份文档是干什么的

记录**已经确认存在、但这几轮刻意没修**的问题。

它存在的意义不是"待办列表" —— 而是防止三种具体的损失：

1. **重复发现。** 同一个问题在下一次 review 里又被当成新问题提一遍，白花时间做判断。
2. **误修。** 有些现象看着像 bug，其实是权衡后的选择（比如"官方没改 flex gap，而是加了个兼容层"）。
   不知道背景的人一动手就把权衡拆了。
3. **遗忘原因。** 「为什么当时不修」比「有问题」更重要。忘了原因，就会在错误的时间修它。

每条都写了**为什么现在不做**和**将来怎么验**。没有这两条的条目不算完成。

编号规则：`C` = 结构性工程，`D` = 需要产品决策，`B-L` = B 档刻意留下，`N` = 本轮新发现。
编号一旦分配就不再变（跨版本引用靠它）。

#### 复盘：为什么这件事拖了这么久，真正难的不是「搬代码」

v79 已经做过一半（`bindEvents` 按屏拆成 11 个嵌套函数），定位成本降了但文件没小。
当时停手的理由是「26 个测试文件做源码级断言，跨文件拆分必须单独一轮」——这个判断是对的。

但真正吃时间的是**另一件当时没预料到的事**：拆分把「闭包里的自由变量」
变成了「注入契约」，而**契约失配不报错**。

拆完第一版时 `npm test` 已经全绿（4463 条断言），一跑浏览器探针，
**点建房没反应**。追下去一共挖出 5 处静默失效：

1. `modalKit.js` 的导出块整块丢失，`api` 成了空对象 → 所有弹窗全哑
2. `cardView.js` 8 个尺寸常量没导出 → 布局计算全变 `NaN`
3. 9 个依赖按值传引用，而 `var` 赋值在创建点之后（`var` 不提升值）→ 永久 `undefined`
4. `settleView` 用了裸 `BIG_TYPES`（住在 `cardView` 里，没注入）
5. `settleView` / `seatSheetView` / `recordsView` 都用了裸 `state`，三个都没注入

第 4、5 条的表现是「房间到第 2 轮起界面不再重绘」，看起来像「提交按钮点了没反应」。

**最难的地方**：`roomStore.js:537` 把订阅回调包在 `try { cb(room) } catch (e) {}` 里，
异常连控制台都不进。是临时给回调套 `try/catch` 抓栈才看见
`ReferenceError: state is not defined at settleView.js:273`。

**留下的教训（已固化成 `pwa/test/module-contract.test.js`，39 项）**：

> 旧守卫查的是「源码里有没有这段文本」。这次的 5 个 bug 全在「两边接得上吗」。
> **守卫站错层级时，全绿恰恰是最危险的信号。**

新守卫的四组断言（都用已知坏样本证过会红）：模块能加载、工厂导出非空、
主文件每个 `NS.key` 都能解析、依赖在创建那一刻**真的已经有值**、
模块读的常量与 `state` 有来源。

### C2 双份统计：`profile.js`（服务端权威）与 `records.js`（本机兜底） —— **已完成（v111）**
<!-- STATUS: closed | v111：抽成 pwa/js/stats.js 双端共用 -->

**状态**：v111 已关闭。新增 `pwa/js/stats.js`（`blank` / `apply` / `fromNets` / `rate`），
服务端 `profile.record` 逐把 `apply`、前端 `records.stats` 整表 `fold` —— **同一段代码**，

**收口时抓到的真分岔（这条债的实证）**：本机那份算的是「连胜计数」（输了返回 0），
云端档案算的是**带符号**值（连败为负）。战绩卡渲染里明明有 `streak < -1 → N 连败` 那一支，
也就是说**本地兜底路径从来没显示过连败**。两处都对得上测试，因为测试各自只测自己那份。

**现象**：场次 / 胜负平 / 胜率 / 连胜 / 最长连胜 / 最佳单场，两套实现。
现在口径一致（有测试对齐），但改规则必须改两处。

**影响**：改一处忘另一处 → 用户看到"战绩页说 12 胜，排行榜说 11 胜"，而且两边都不报错。

**为什么现在不做**：抽公共模块需要服务端和前端共用一份 JS（构建步骤），
而这个项目是**零构建**的（直接 `<script src>` 加载）。为了一致性引入打包器，代价过大。

**建议做法**：退一步 —— 在 `records.js` 顶部写死一条注释指向 `profile.js` 的对应函数，
并在 `pwa/test/records-ai.test.js` 里保持一条「与 server 同口径」的对照断言（现在已有，别删）。

**怎么验**：故意改 `profile.js` 的一条规则，跑测试，`records-ai.test.js` 必须红。

### C6 三个已知的「会显示字面量」的崩溃点 —— **v79 已修**
<!-- STATUS: closed | v79 -->

| 位置 | 触发条件 | 改之前会显示 | 改之后 |
|---|---|---|---|
| `esc(g.winnerNickname)` | 结算结果对象异常、缺字段 | 字面量 `undefined` | 空 |
| 结算行的 `p.nickname + ...` | 昵称为 `null` | 字面量 `null` | `?` |
| `state.myId.slice(-4)` | `myId` 是空串 | 退化成「玩家」 | 「我」 |

改法：`esc()` 开头把 `undefined` / `null` 直接转 `''`（保留 `0` / `false` 的显示，
所以判定用的是 `=== undefined || === null`，不是 falsy）；两处 `'玩家' + myId.slice(-4)`
合并成 `defaultNick()`，空 id 时返回「我」。

### D7 localStorage 配额 —— **v79 已修**

于是配额一满就是「这局打完了，战绩页里没有」，而且**没有任何提示**。玩家能观察到的
唯一现象是「战绩偶尔会丢一局」，归因成本极高。

**v79 的做法**：`rawWrite` 改成三态 —— `'ok'` / `'trimmed'` / `false`。

1. 先尝试完整写入；
2. 装不下就**自己腾地方**：列表本来就是 `endedAt` 倒序，`slice(0, n)` 天然保留最新的。
   两段降级：砍到一半（并丢掉这些记录的 `replay` 字段）→ 只留最新 10 条；
3. 还写不进才返回 `false`，`Records.add` 转成 `{added:false, reason:'writeFailed'}`。

`game.js` 的 `noticeRecordsWrite()` 接住三种结果，**每局最多提示一次**：
`trimmed` → 「手机存储紧张，只保留了最近的战绩」；`writeFailed` → 「手机存储已满，
这局没存到本机战绩（云端记录不受影响）」。写「云端不受影响」是必须的 ——
不说这句，玩家会以为整场战绩都没了。

验证：`pwa/test/records-quota.test.js`（15 项）。用容量可控的 mock 逼出三种结果，
不是真塞 5MB —— 真塞 5MB 只能证明「不崩」，证明不了「裁掉的是最老的、留下的是最新的」。

### D8 结算页的「冠军」按当前分数取首行 —— **v104 已定口径**
<!-- STATUS: closed | v104 定口径 -->

**原状况（代码事实）**：`settleListEl()` 里 `sort(byScoreDesc)` 之后 `if (i === 0)` 挂皇冠。
冠军是有的（金底 + 🏆 + 名次角标），但口径是「结算那一刻谁分最高」，两个地方会歪：
弃局者的分数在离开那一刻冻结，可能仍是全场最高 → **走了的人戴皇冠**；
同分时 `Array.sort` 是稳定的 → 并列第一由**入座顺序**决定，界面一个字没说这是并列。

**定成什么**：抽出纯函数 `settleRank(players)`，两条规则同时成立：

| 规则 | 实现 | 玩家看到 |
|---|---|---|
| 弃局者不计名次 | 从排名池里剔除，按分数降序沉到末尾，`rank = 0` | 排在最后、整行压暗、角标「—」、aria 念「已离开，不计名次」 |
| 同分并列同名次 | 竞赛式排名 1,1,3；`tied` 标记 | 两个相同的数字，前面加「=」；并列冠军另挂一枚「并列」胶囊 |

冠军 = 所有 `rank === 1` 的人，**可以不止一个**；全员弃局时没有冠军（不给走了的人发奖杯）。

**为什么这样定，而不是另外两种**：
- 不改排序只在弃局者夺冠时加一句说明 → 皇冠还是落在走了的人头上，读到的是「他赢了」；
- 冠军只从打完的人里选、同分仍按座位 → 治了一半，并列第一照样由谁先坐下决定。
两者都留了一个「同一份数据、两个答案」的口子，而这一整轮改造就是在消这类口子。

**代价**：弃局者从列表中间挪到末尾，**`i + 1` 不再等于名次** ——
`settle-replay.test.js` 有两条旧断言守的正是 `i + 1`，已改成守 `r.rank`（并新增一条「不许再用 `i+1`」）。

**验证**：`pwa/test/settle-champion.test.js`（48 项，**真跑纯函数**，不是 grep）：
弃局者 40 分不夺冠、同分两人都是冠军且第三名是 3、全员弃局无冠军、0 分并列、
负分仍排名次、不改入参数组。加上 `settle-replay`（56）与 `handlimit-settle-parity` 全绿。
**没有真机验证**：并列只影响一并列就出现的那两行，量不了也只能看 ——
`node scripts/probe-handlimit-settle.js` 覆盖的是两条终局路径的一致性，不碰排序口径。

**没做**：弃局者的「净胜」要不要从战绩胜负统计里剔除 —— 那是战绩页口径，与本页无关，别混进来。

### N1 房间页「补 AI 队友」按钮文字被挤成两行 —— **v79 已修**
<!-- STATUS: closed | v79 -->

**现象**：房间页底部三个按钮 `.room-actions .ghost-row`（补 AI 队友 / 结束本局 / 离开房间），
在 390 宽下第一个按钮的「补 AI 队友」断成「补 AI 队」+「友」，中间那个「友」字单独一行。

**根因**（记录时写的是「按钮太窄」，实测不是）：`flex: 1` 把三颗按钮压成**等宽**，
而中文允许逐字断行 —— 浏览器在「挤在同一行 + 从词中间劈开」和「整体换到下一行」之间，
选了前者。所以问题不是宽度不够，是**没有禁止断字**。

**v79 的做法**：两句话一起说 ——

```css
.room-actions .ghost-row { display: flex; flex-wrap: wrap; gap: 12px; }
.room-actions .ghost-row .btn { flex: 1 1 auto; margin: 0; white-space: nowrap; }
```

- `nowrap` 让文字不许从词中间断；
- `flex: 1 1 auto` 取代 `flex: 1`，宽度按内容分配，三颗按钮不再被迫等宽；
- **不能加 `min-width: 0`**：那会把换行变成「文字溢出按钮」，比现在更糟。

另外横屏那条规则（`.ls … .ghost-row { flex-direction: column }`）必须补 `flex-wrap: nowrap`
—— column + wrap 在高度不够时会另起一列，三颗按钮会横着排成三列。

**实测结果比预期更好**：320 / 360 / 390 / 430 四档**都在一行内放下了**，一次都没换行；
横屏三颗各占一行。原来预想的「2+1 换行」没有出现。

**怎么验**：`node scripts/probe-room-actions.js` 一次跑完四档竖屏 + 一档横屏，
判据是 `Range.getClientRects()` 的矩形个数（= 文本被排成几行），
不是高度 —— 高度会被 line-height 和 padding 干扰。
另有 `pwa/test/room-actions-fit.test.js`（12 项）钉住这几条 CSS 约束。

### N2 线上 `manifest.webmanifest` 与 `apple-touch-icon` 一律 403 —— **v79 发布后冒烟发现**
<!-- STATUS: closed | v79 -->

**现象**：用真实浏览器打开线上地址，控制台里躺着 5 条错误，其中两条是：

```
Failed to load resource: 403  /manifest.webmanifest
Manifest fetch from .../manifest.webmanifest failed, code 403
```

`/icons/apple-touch-icon.png` 同样 403（同样不带 `?sharecode=` 的请求）。

**根因**：部署网关要求**每一个请求**都带 `?sharecode=`，不带的一律 403。
页面自己发起的两类请求能活下来，靠的是不同的补丁：

| 请求 | 谁发起 | 有没有补 sharecode | 结果 |
|---|---|---|---|
| `js/*.js`、`css/*.css` | 页面 `<script>` / `<link>` | **SW 的 fetch 处理器** `withShare()` 拼上 | 200 |
| `sw.js` 本身 | `navigator.serviceWorker.register()` | 注册时手工拼 `location.search` | 200 |
| `manifest.webmanifest` | **浏览器内部**（解析 `<link rel=manifest>`） | 无 —— 不经过 SW，也没有机会拼 | 403 |
| `apple-touch-icon.png` | 同上 | 无 | 403 |
| manifest 里声明的 `icons[]` | 浏览器（安装时按 src 抓） | 无 | 403 |

关键点：**manifest 与图标的抓取不经过 Service Worker**（SW 只拦截页面发起的 fetch），
所以 SW 里那套 `withShare()` 对它们完全无效。`<link rel="manifest" href="/manifest.webmanifest">`
是绝对路径、不带 query —— 换谁来看都是 403。

**影响（诚实评估，不夸大）**：

- 安卓 Chrome：`manifest` 拿不到 → **装不出 WebAPK**（没有独立窗口、没有启动图、
  图标取不到）。用户仍能「添加到主屏幕」，但那只是一个浏览器快捷方式，
  打开是带地址栏的标签页，不是 `standalone`。

### N5 PWA（iOS 26 standalone）底部一条纯色带 —— **v81 已修，待真机复验**

### N8 斗牛 5 张组在圆桌上只有 69×97，低于文档自定的 82×115 —— **v89 已修**
<!-- STATUS: closed | v89 -->

**事实**（用线上同一函数 `SlotLayout.cardSize` + 实测输入算的，`BAND_INNER_W = 629`、竖屏组槽 537）：

**根因**：`slotLayout.cardSize()` 在 dense 下的横向上限是 `bandInnerW × widthRatio`。

  （写 `image/jpeg` 不代表真是 JPEG）；pid 白名单清洗（否则是路径穿越）；
  300KB 上限（256×256 / q0.82 实际 12~20KB）。
- 取图 `GET /api/avatar/<pid>?v=<版本>`：**版本号是唯一访问凭据**，
  不带 v 一律 404 —— 谁传过头像因此不可枚举；带对 v 给一年 immutable 缓存
  （URL 里有版本号，换图就换 URL，不会缓存发霉）。
- `POST /api/me/avatar/photo` 收**裸二进制**：JSON 接口的 `BODY_MAX` 只有 16KB，
  base64 还要再涨 1/3，根本塞不下。
- 客户端 canvas 压到 256×256（短边铺满 + 居中裁切，不拉伸），传完 `revokeObjectURL`。
- 「最后一次动作生效」只有一条规则：选预设 → 服务端清照片；传照片 → 照片覆盖预设。
- ★ 两条删号路径都 `avatars.remove(pid)`：档案删了图还在，等于用户照片留在服务器上。
- 举报 `/api/me/avatar/report` 落 `data/avatars/reports.log`（理由里的换行被抹掉，
  否则一条举报能伪造多行日志）。

开关本身要满足 `rollback-contract` 的两条：`avatarUploadFlag()` + `?avatarupload=0/1`，
且兜底必须是 `CONFIG.AVATAR_UPLOAD === true`（缺省当**关**，不是当开）。

### N24 提交后点「改一下」，别人全交会**用旧分组把他结算掉** —— **v106 已修**
<!-- STATUS: closed | v106 -->

**怎么发现的**：用户实测 —— 「现在提交后撤回牌的话，如果期间其他人全提交，就算自己没改完提交
也会被动提交，不符合设计的初衷，应该确认撤回的人也提交了再结算当前轮次」。

**根因不是判断写错了，是服务端根本不知道有人在改**：

| 层 | 旧实现 | 结果 |
|---|---|---|
| 前端 | 点「改一下」→ 只设 `state.reviseRound`（纯 UI 变量） | 服务端一无所知 |
| 状态机 | `p.submitted[rkey]` 一旦 true **永不回落** | 「全员到齐」把他算成已交 |
| 结算 | 最后一个人提交 → `allSubmitted` 成立 → 立刻 `settleRound` | **用他还没改完的那份旧分组结算** |

他的意图明明是「我要改」，却被自己上一版代表结算了，全程没有任何提示。

**修法**：新增 `p.revising`（正在改的轮次号），判定「定稿」多一层。

| 改动 | 位置 | 为什么 |
|---|---|---|
| `isRoundLocked(p, round)` | `stateMachine.js` | **三处「到齐」判定统一走它**。以前是 `submitGroups` / `forfeitRound` / `settleIfAllIn` 三份手抄的同一句，注释里还写着「口径要与另外两处保持一致」—— 那说明它已经在靠人记着了 |
| `beginRevise` / `cancelRevise` | `stateMachine.js` + `hub.js` + `roomStore.js` | 「是否在改」决定能不能结算，是**规则**不是视觉状态，必须在服务端 |
| `_armOneSplitTimer` 改判 `isRoundLocked` | `hub.js` | 原来「已提交就不挂计时器」，正在改的人因此**没有兜底**。他一旦掉线，全桌吊死 |
| 超时语义分叉 | `forfeitRound` | ★ 有旧分组的人超时 = **放弃修改**（按旧分组算），不按弃权（空分组）罚。否则「点过一次改一下」反而比「什么都不做」更亏，以后没人敢用这个功能 |
| `_dropSplitTimer` | `hub.js` | 提交后摘掉「改牌倒计时」，别在 Map 里留幽灵任务 |
| 座位卡 / 进度环 | `game.js` | 显示「正在改」而不是「已提交」；进度环改用同一个 `isRoundLocked`，否则会出现「已提交 4/4 但就是不结算」——玩家只会以为卡死了 |

**「不改了」这个出口**：`#btn-revise` 一个按钮两个语义（已提交 → 「改一下」，修改态 → 「不改了」）。
必须给后悔的出口 —— 进入修改态后他**不再算定稿**，全桌都在等他；没有出口的话，
误点一下就只能真改一次（消耗唯一额度）才能让这一轮走完。取消**不消耗**额度。

**怎么验**（`pwa/test/revise.test.js`，52 项）：
- 对照组证明这条测试不是空转门：**不走 `beginRevise` 就会结算** —— 用新代码模拟老行为
- 证红：把 `isRoundLocked` 里 `p.revising !== round` 换成 `return true`，该文件当场挂 11 项
- 源码守卫：`stateMachine` 里三处判定都调 `isRoundLocked`，旧的「弃权 或 已提交」手抄版已不存在

### N25 六张牌全入组后无法拖动交换位置 —— **v106 已做**
<!-- STATUS: closed | v106 -->

**怎么发现的**：用户实测 —— 「现在不支持六张牌都已放入卡池后，拖动一张牌去交换另一张牌，
只能先把想换位置的两张牌先放一张到手牌位置，再把另一张放到空位，再把手牌放到最后的空位」。

**根因**：`moveSlotCard` 里有一句「目标组满了就 `flash('这组已经满了')` 拒绝」。
六张全入组之后三组都是满的，**任何**拖拽目标都是「满的」，交换这条路根本不存在。
而 `removeCard + placeCard` 组合也做不到：`placeCard` 同样拒绝满组。

**修法**：新增 `StateMachine.swapCards(round, groups, a, b)` 纯函数 ——
交换**不需要容量校验**，两组张数一进一出，前后完全相等。
拖拽侧改两处：
1. `highlightDropTarget` **先判牌、再判组**：槽牌就住在组里，组的矩形把牌整个包住，
   判反了「落到某张牌上」永远会被解析成「落到这个组」，交换永远触发不了
2. `endDrag` 的交换分支必须排在 `if (!d.slotKey) return;` **之前** ——
   落到牌上时 `slotKey` 是显式置 null 的，顺序错了就静默失效（拖过去没反应）

顺带支持「手牌 → 槽牌」也有同样语义（手牌那张顶掉槽里那张，被顶掉的回手牌）。

**同组内交换明确拒绝**：组内顺序不参与任何结算（比的是牌型，与排列无关），换了等于没换，
悄悄当成成功是在骗人。落点判定阶段就挡掉，不亮高亮。

**视觉**：`.card-box.drop-swap` 金色描边 + 抬起，必须和 `.slot.drop-hover`（整组接收）分得开 ——
否则「换位置」和「塞进这组」会变成同一个手势、两种结果。

**怎么验**：
- `pwa/test/swap.test.js`（35 项）：张数不变、往返回到原样、三种拒绝都不动草稿、五种源码守卫
- `probe-ui-flow.js` 新增「对局·交换」场景（全矩阵 12 视口都跑）：真的派发
  `pointerdown/move/up` 拖一次，再比对两张牌是不是互换了组。
  **单测证明不了「手指拖过去真的会换」** —— 中间隔着 `elementFromPoint` 的落点判定和一串接线

现在点一次头像 = 看到全部，与战绩页点开的那张卡一字不差。

**顺带修掉的三件小事**：

1. **只有一个分档时隐藏分档条**。点自己（或关掉表情开关）时面板里只剩「信息」一档 ——
   一个只有一个选项的切换条不是导航，是装饰：看起来能点，点下去什么都不会变。
2. **异步填充后必须重新定位**。`placeSeatSheet()` 拿 `sheet.offsetHeight` 算落点，

3. **样式作用域漏了一半**。`.pf-record` / `.pf-note` / `.profile-box p` 这些规则挂在

   没有字号也没有颜色，还带着浏览器默认的 `p` 边距，和下面的「最近 5 局」糊在一起。
   旧版信息档只用了三个数字框（那是全局样式）所以从没暴露过。
   **规约**：`profileBodyHtml` 里出现的每一块，样式必须同时覆盖 `.profile-box` 和 `.ss-info`。

只剩三个数字，而三个数字在上面一行 `.ss-sub` 里已经有了「分数」这个最常看的那一个 ——
那样会变成"为了省高度而删掉唯一值得看的东西"。

**怎么验**：新增 `scripts/probe-seat-info.js`（`npm run probe:seatinfo`），四个视口实测：
390×844 / 360×640 / 728×348 / 844×390 全部「面板完整落在舞台内并留出 16px 边距」。
最紧的是 728×348：`top 158 + 高 602 = 760 = 舞台高 776 − 16`，**正好夹在极限上** ——
不重排的话底边会到 821，直接出屏。
另外两条守卫：分档条在单档时必须隐藏、信息档必须四个区块齐全（stats / record / recent / note）。

## 6. 明确接受的取舍（不是问题，别"修"）| 项 | 为什么这是对的 |
|---|---|
| 大量 `var` + ES5 写法 | **有意为之**，要兼容老 WebView。不要"现代化"成 `const/let`（会直接用不了） |
| `/ws` 不被 Service Worker 拦截 | 联机必须在线，离线拦截只会让"断线"表现成"点了没反应" |
| 令牌 90 天 | 熟人局场景，"每次打开都要重新登录"的体验损失大于理论风险 |
| 无手机号注册 | **优点**，不是缺陷。没有短信成本、没有合规负担、没有手机号泄露面 |
| 昵称唯一（v76 起）而非账号名唯一 | 账号名是登录凭据、昵称是展示名，两者规则不同是对的 |
| 心跳用协议层 ping 而非 JSON ping | 浏览器网络层自动回 pong，页面 JS 被挂起时仍然有效 —— 这样才能区分"切后台"和"真断线" |
| 兼容层用 JS 检测而非 UA 判断 | 国产浏览器 UA 完全不可信，且会随内核更新失效 |
| 兼容层不预缓存 | 见 B-L4，收了也命中不了 |
| **分数可以跌成负数，人继续打**（v103） | 20 分本金只够扛 2~3 把，留「见底即结束」会让 5/10/15/30 四档全部变成摆设。牺牲「见底的心跳感」，换「选的局数真的算数」。**不要重加爆分终止**——那会连带恢复「第 1 组见底、后两组输赢蒸发」的不公平 |
| `bustedIds` / `p.out` 恒空但字段保留 | 老战绩的回放数据里真有这些字段，删了会让历史回放渲染出 `undefined` |
| `END_REASON_TEXT.scoreZero` 文案保留 | 同上：老记录的 `endReason` 就是 `scoreZero`。删这一行等于让老战绩念成「已结束」 |
| 局数档位不记忆（每次开弹窗回 10） | 产品口径是「不选就是 10」。加 localStorage 是 1 行的事，但那就不再是「不选就是 10」 |
