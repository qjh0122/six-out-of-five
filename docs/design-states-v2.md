## ② 现行四态规格（压缩版）

> v1 作废后，**四态的现行值以本表为唯一复核载体**；v1 `①-a / ①-b` 仅作历史参考，不再作为判据。标 ★ 的格是 v137 改判项，对应 ① 登记表。未标 ★ 的标题、视觉三要素与触发条件主体逐字取自 v1 `①-a`，此处只作索引，不重述理由与自证矩阵。

| 态（值） | 触发条件 | DOM 载体 | 视觉三要素（插画 / 按钮数 / 会不会自己走开） | 标题 | 副文案 | 与另外几态一眼可分的依据 |
|---|---|---|---|---|---|---|
| `empty` | `hasData === false` 且不处于 loading / fail / offline；判定顺序末位 | `#records-empty`（`.rp-empty`）；**互斥组** | 有 188px 插画 / **1**（「创建房间」） / **不会** | 还没有战绩，去开一局吧 | 打完一局自动记下 | 全站唯一「有插画 + 单主 CTA + 居中满屏」 |

**表下四条（现行口径，供复核）**

1. **判定顺序** `offline > fail > loading > empty > data` 沿用 v1 `①-c`，v2 未改判；唯一真源仍是 `#screen-records` 上的 `data-rstate`（值域五值）。
2. **★ F2 完整口径**：判据是「`#screen-records` 真的露着」（判 `state.screen` 不成立：冷启动那一段它有值而屏还 hidden）；`showScreen()` 末尾必须重算 `setNetBanner(!isOffline())`，否则从战绩页退到首页横幅会一直藏着 —— 那是把「让位」写成「删掉」。S8（离线原因不寄生 toast）不受影响。此条**覆盖 v1 `⑥-12` 前半句**。
3. **★ R8 完整口径**：仍是一个块、一张文案表（`STATE_TEXT.offline.subPanel`），不新建块、不给施工方自选改字；`is-strip` 那句底下真有记录，为真；`is-panel` 那句不承诺本机有记录，也为真。
4. **互斥判据**：`{loading, fail, empty, data}` 同时可见数 **≤1**（R2，取代 v1 `⑤-c` 的「恰有一个」）；250ms 门槛期内 0 个合法，稳定后 = 1；`offline` 不在该组。

## ③ 现行数字阶梯

> **数值终值唯一出处**：`pwa/css/style.css` 的 `:root`（`--num-1..4` / `--num-u1..2`），逐选择器映射见 `build-numbers-v1.md §3`。本表「数值」列一律写「见 `:root`」，**不另立数值表**与它并存。
> 档数口径：v1 `③-a` 名义三档（T2 内含主 / 密两个字号），现行按 N1 记为**四档 + 两档单位**，用途不变，只是把 T2 的主 / 密各记一档。

| 档（令牌） | 数值 | 用途 | 一个真实用例 |
|---|---|---|---|
| T1 `--num-1` | 见 `:root` | 沿用 v1 `③-a` T1 用途列（一屏唯一的结论），未改判 | 战绩页累计净胜 `.rp-sum-value` / `#rp-net` |
| T2 主 `--num-2` | 见 `:root` | 沿用 v1 `③-a` T2 主档用途列（并列关键值、独占一行宽），未改判 | 胜 / 负 / 平三卡 `.rp-gnum`；结算冠军净胜（★ N6 横屏同档） |
| T2 密 `--num-3` | 见 `:root` | 沿用 v1 `③-a` T2 密排用途列（列表行内 / 同排 ≥3），未改判 | 结算行净值 `.settle-net`；榜单行净值 `.rank-net`；纪录条 `.rp-best-v b` |
| T3 `--num-4` | 见 `:root` | 沿用 v1 `③-a` T3 用途列（场次、胜率、名次、时间、x/N），未改判 | 列表口径 `.rp-list-count`「共 12 场」；榜单名次 `.rank-no` |
| 单位 `--num-u1` | 见 `:root` | 配 T1 的单位与分母（★ N3：分母改归单位档） | `.rp-unit`；成就 `/ 35` 的 `.ach-count span` |
| 单位 `--num-u2` | 见 `:root` | 配 T2 的单位 | `.rp-best-v i` |

**三条硬约束**

1. **阶梯封闭（N1 / N2，取代 v1 `③-c` 硬约束与 `⑥-9`）**：数值元素 `font-size` 必须 ∈ `:root` 的 `--num-1..4`，单位必须 ∈ `--num-u1..2`；判「在不在梯子上」，不再判「同屏去重后几个」。任何 `font-size` 想写数值只能写 `var(--num-*)`，要加档先改文档，不许在 CSS 里现编。40 / 34 / 30 / 62 / 68 / 84 的共同点是「不在梯子上」，不是「多了」。现行断言：`pwa/test/number-scale.test.js` + `scripts/probe-numbers.js`。
2. **采集口径（N3 / N4）**：「数 + 量」按 v1 `③-b` 自己「读起来是一个词」的说法视为一个词，走正文层级、**不进阶梯**；判据只盯纯数字与百分比；分母 `/N` 归单位档。`position:absolute` 的角标胶囊（`.settle-pos`）按**图形**处理豁免，**豁免写进断言**（分类器自测样本），不是默默跳过。
3. **屏宽与朝向（N5 / N6）**：媒体查询只允许在令牌内**换档**，不许出现梯外值；舞台已按屏宽 `scale()` 过一遍，不得在同一元素上再缩一次（两条 `.ach-count b` 媒体覆盖已删：390 主力机型曾比 430 的字还小）。**横屏冠军净胜与竖屏同档，不许更小**。另沿用 v1 `③-b / ③-d` 与 `build-numbers-v1.md §4`：单位严格小于所属数字、同屏 T1 ≤ 1、榜单名次与净值各自只有一号。
