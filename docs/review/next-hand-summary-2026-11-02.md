## 一、合并后的一句话

**顺利路径是通的，真实牌桌撑不住。** 两个域从不同证据出发，指向同一件事：
**这段流程把「结算页」当成了「对局中」的一个瞬间，而不是一个独立阶段。**
于是掉线、走开、少人、不点按钮这些「结算期本来就该允许的事」，全被对局中的规则处理了。

| 谁 | 它的原话 | 合并后的含义 |
|---|---|---|
| 体验侧 | 「结算期整段时间仍在用『对局中』的规则处理人」 | 玩家在结算页做的事（看战绩、切出去回消息）被当成「弃权/弃局」 |
| 状态流侧 | 「这套流程能撑住『大家都稳稳坐着』的牌桌，撑不住真实牌桌的『有人走开一下』」 | 同上，且**没有任何一条测试覆盖结算期的这条分支** |

## 三、三个方向（递进，可以只做 A）

| | A 最小修补 | B 中等 | C 重做这一段 |
|---|---|---|---|
| **改什么** | ① 结算期掉线只标「离线」不算弃局（判据用 `phase`，不加字段）② 四处「局/把」术语对齐 ③ 结算页加一句「下一局分数从 0 开始」④ 庆祝音改用与名次同一份口径 | A + ① 就位态给「结束这场」活路，并允许「已准备的人一致同意就不等他」② 开新局前加一步人数确认 ③ 被移出的人被告知「打完后用房号还能进」 | A+B + ① 结算页顶部加「本局冠军」块（净胜 + 分差）② 主操作改成「再来一局（同样 N 把）」= 报名即准备 ③ 结算后进入**候场**：座位全保留、不续局的人变旁听、把数档位这一段可改 |
| **代价** | 0.5~1 人日 | 1.5~2.5 人日 | 4~6 人日 |
| **风险** | 低（只碰展示与 `left` 的语义分支） | 中（新增协议动作，要处理幂等/并发/掉线） | 高（阶段语义或座位语义二选一，广播/回放/战绩/成就/探针全要重算） |
| **关掉哪几条** | 2 个 P0 里的 #1 + 4 条隐患 | 再加 P0 #2 与「被踢走」这类 | 全部 + 收尾仪式与续局效率 |

## 四、两个域都明确说「不要做」的

| 不要做 | 理由（两边一致） |
|---|---|
| 恢复房主一键开下一局 | 报名制就是为了避免「房主手快，正在看回放的人被顶出结算页」；出口是「不等他」，不是「房主说了算」 |
| 给「准备」加倒计时到点强开 | 会把没准备好的人硬塞进一局，与「没点的人不被拖走」的承诺冲突 |
| 做观战 / 旁听牌桌 | 一局 20+ 分钟，没人看别人打；真实需求是「留在房里等下一局」 |
| 把续局分数改成延续 | 会推翻「净胜 = 最终分」的口径与成就/排行榜的全部算法 |
| 为提高回放上限扩 `PACKS_MAX` / 字节预算 | 撑爆本地存档会让整页战绩读不出来，比少 6 把糟得多 |

## 五、我的建议（制作人口径）

**先做 A，不做 B/C。** 理由：

1. A 关掉了「玩家什么都没做、冠军被改写」这个最伤的一条，代价不到一天；
2. B 里的「不等他」涉及新增协议动作，与 `next-round.test.js` 现有 12 条不变量交织，
   值得单独一轮，而且**先把 A 发出去观察一周**更稳；
3. C 的「候场 / 旁听」是一套新的座位语义，会牵动成就、回放、战绩的每一处「谁是玩家」的判断 ——
   在 P2-3（房间态持久化）没做之前动它，重启丢房的问题会一起放大。

**如果只让我改一条**：改 QA 的 R1（结算期掉线不算弃局）。它是唯一「玩家什么都没做就受损」的问题。

## 六、本报告没证明的事

- 两份报告都**没跑探针、没真机试玩**（快照里跑会污染主仓），所以「手感」类判断不在结论里。
- R1 的「约 3 分钟」是 `心跳 30s × 2 + 宽限 90s` 的推算值，没有实测计时。
- 「4 个玩家里有几个会切出去」这类频率判断**没有数据**，只有场景推演。
