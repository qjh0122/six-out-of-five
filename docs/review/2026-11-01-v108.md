### 1.2 屏级覆盖：完整

`index.html` 里一共 7 个 `screen-*` 容器，`probe-ui-flow` 全部走到：

`screen-auth` ✅ `screen-home` ✅ `screen-room`（准备中）✅ `screen-game`（分牌/交换/已提交）✅

**这一项要记一笔：屏级覆盖是完整的，没有「某个页面从来没被自动化碰过」。**

### 1.3 但「全量」的四个维度，只达标 3 个

| 维度 | 达标? | 说明 |
|---|---|---|
| ① 屏覆盖 | ✅ | 7/7 screen + 4 弹窗，见上 |
| ② 视口覆盖 | ✅ | 12 × 13 = 156 屏；机型闸门另 23+24 档 |
| ③ 数据正确性 | ✅ | `e2e-score` 用独立引擎复算，不是「画出来了就算过」 |
| ④ **路径覆盖** | ❌ | **只有 happy path。异常路径几乎为零** |

第 ④ 项的实测数据（`grep` 全量脚本）：

| 场景 | 单测覆盖 | UI 自动化覆盖 |
|---|---|---|
| 断线 / 重连 | **9 个文件** | **0 个探针** |
| 越权 / 作弊 | 1 个文件 | **0 个探针** |
| 并发 | 3 个文件 | **0 个探针** |
| 多标签页 | 0 | 2 个探针（`probe-multi-tab`）✅ |
| 超时 | 36 个文件 | 5 个探针 |

**断线重连这一行最刺眼**：单测有 9 个文件在管，UI 层一次都没在真浏览器里走过。

而这恰恰是 `journey.js` 存在的理由 —— 它头部写着：

> 「全量单测当时 1953 项全绿，但曾经有一条真实用户必经的路径**一条断言都没有**：
>   打开页面时建了 WS 连接（此时未登录）→ 用户登录成功 → 复用那条未鉴权连接 →
>   30 秒后被服务端踢回登录页。这个 bug 单元测试测不到，不是覆盖率不够，
>   而是它**不是某个函数错了**：每个函数单独看都对，错的是「先建连、后登录、复用」这个**顺序**。」

断线重连是**同一类问题**（时序 + 顺序），却仍然只有单测。

## 三、三个结构性缺口

### 缺口 1：UI 自动化完全不在 CI 里 —— 这是最要紧的一条

CI（`.github/workflows/test.yml`）只做三件事：

1. `node --check` 全部 `*.js`
2. `npm test`（扫 `pwa/test` + `server/test`，**109 文件 / 4502 断言**）
3. 检查 `*.tmp` 残留

**36 个探针 + `journey` + `e2e-score` 一个都没进。**

#### 为什么这一条最紧急：v108 就是活证据

v108 拆分完成后，`npm test` **4463 条断言全绿**，CI 会一路绿灯。但真浏览器里：

> **建房 / 账号 / 规则 / 战绩 —— 所有弹窗全哑**（`modalKit.js` 导出块整块丢失）。
> 另外 4 处静默失效：布局算出 `NaN`、9 个依赖永久 `undefined`、
> 结算页 `render()` 抛异常、房间到第 2 轮起界面不再重绘。

唯一抓住它的是**手动跑的 `probe-ui-flow`**。如果那天没跑探针，这个版本会直接发出去。

> **结论：当前 UI 层唯一的保险是一道不在 CI 里的门，它开不开取决于人记不记得。**

### 缺口 2：10 个红探针长期无人管

backlog 里 N18 已经写清了原因和策略（「修一个用一个，不做顺手全改」），
但记录至今**没有一条被执行**。红的时间至少跨了 v99 → v108，**9 个版本**。

### 缺口 3：想在 CI 里跑，当前写法也跑不了

8 个脚本把 Windows 浏览器路径写死了：

```js
spawn(process.env.EDGE_BIN || 'C:/Program Files (x86)/Microsoft/Edge/Application/msedge.exe', ...)
```

- 支持 `EDGE_BIN` 覆盖的：**只有 1 个**（`probe-ui-flow`）
- CI 跑在 `ubuntu-latest`，**这 8 个直接起不来**

所以「没进 CI」不只是「忘了加」，是**当前实现也加不进去**。
好消息：`probe-ui-flow` 用的是 `--headless=new` + CDP over WebSocket，这套在 Linux Chromium 上基本通用，
接进 CI 的技术门槛不高。

导致 v47/v48 写的 7 套测试**从来没被执行过**，而当时报告的「通过 1378 项」里根本没算它们。

## 六、机制与数值：增量

上一轮（`REVIEW-2026-11-01.md`）的核心结论**仍然成立**，本轮无新增问题：

- **斗牛一组占一把的 49.9%**，而它只有 6 种分法；第一轮三组共用一手牌、60 种分法，只占 44.7%。
  这是「最费脑的一轮拿不到相应回报」的倒挂。
- 但那轮明确判定**不能立刻改**：只有 L1 证据（模拟），缺 L2（真实玩家耗时/感受）。
  强行调 `DOUNIU_NONE_PENALTY` 属于「凭模拟加码」，违反归因优先于加码。
- 数值自洽性 **B**：零和、无通胀、无单向投放。`INITIAL_SCORE` 归 0 之后，
  那个参数彻底失去功能，注释里已写明这是「唯一自洽的值」而不是疏忽。

`pwa/js/config.js` 每个参数都带大段「为什么是这个值」的注释 —— 这是全仓质量最高的文件之一，
包括 `AVATAR_UPLOAD` 为什么默认关（要先有举报入口 + 有人看日志 + 用户协议）这种
把风险和处置一起写清的做法。

## 七、建议（按 ROI 排序，每条带验收标准）

### 建议 1（最高优先）：把 `journey` + `probe-ui-flow` 单档接进 CI

| 字段 | 内容 |
|---|---|
| `decision` | CI 增加一个 UI job，跑 `journey.js` + `ONLY="390×844" node scripts/probe-ui-flow.js` |
| `evidence_level` | L1 —— v108 实证：4502 断言全绿但所有弹窗是死的，只有 probe-ui-flow 抓住 |
| `primary_bottleneck` | 缺口 1：UI 保险不在门禁内，靠人记着跑 |
| `released_variables` | 2 个：① CI 增加 UI job ② 7 个硬编码路径的脚本改成读环境变量（`EDGE_BIN`/`CHROME_BIN`） |
| `success_criteria` | **必须先证红**：故意把 `modalKit.js` 的一行导出删掉，CI 必须变红；恢复后转绿 |
| `rollback_trigger` | 若连续 5 次 CI 出现「本地绿 CI 红」且原因是环境差异，降级为 nightly 定时任务而非阻塞合并 |

成本估计：CI 加约 **5 分钟**（journey + 单视口 13 屏）。这是可控的。

> 注意：**不要一开始就上 12 视口全矩阵**（22 分钟）。先 1 档拿到「门存在」这个事实，
> 视口矩阵继续留在发版前手动跑。单变量释放。

### 建议 2：修 10 个红探针，按「修一个用一个」

| 字段 | 内容 |
|---|---|
| `decision` | 逐条修 N18 记录的探针维护债，不做批量顺改 |
| `evidence_level` | L1 —— 10/10 在 v107 基线复现，确认是脚本过时而非功能坏 |
| `primary_bottleneck` | 缺口 2：脚本停在 v98 流程假设（建房多了一步选局数） |
| `released_variables` | 1 个：每次只改一个探针脚本 |
| `success_criteria` | ① 修完转绿；② **在 v107 基线上仍红**（证明改的是脚本，不是把功能拉回去凑绿） |
| `rollback_trigger` | 若修的过程中发现是功能真坏（不是脚本过时），立刻停手转成功能修复，并单独记账 |

优先顺序建议：`probe-emoji`（0/2，整块无覆盖）→ `probe-table-ready`（16/17，准备态是主流程）→ `probe-tenhalf`（0/2）→ 其余。

### 建议 3：补一条断线重连的 UI 探针

| 字段 | 内容 |
|---|---|
| `decision` | 新增 `probe-reconnect.js`：真浏览器里断 WS → 重连 → 验证界面状态正确 |
| `evidence_level` | L1 —— 单测 9 个文件覆盖，UI 层 0 覆盖；同类 bug（未鉴权连接复用）历史上真出过 |

| `released_variables` | 1 个：只新增探针，不动产品代码 |

| `rollback_trigger` | 不涉及产品改动，无回滚需求 |
