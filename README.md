# 六选五 · 联机扑克

2~5 人好友房。一副 53 张（52 + 大王），每人 6 张，两轮分牌比大小。
建房时选本局打几把，**打满为止**；分数可以跌成负数，不会因此提前结束。

打完一把记一次净胜。

- **零运行时依赖**：前端是静态文件，服务端是单进程 Node（无 npm 依赖）
- **服务端权威结算**：同一账号换设备，分数和战绩跟着走
- **可离线安装**：PWA，安卓可装成独立窗口，iOS 可加到主屏

> **线上部署在私人托管环境，需要进房口令，所以本文不提供公开试玩链接。**
> 想跑一份完整的，看下面的「跑起来」——不需要数据库、不需要构建步骤。

## 怎么玩

| 轮次 | 分组 | 张数 |
|---|---|---|
| 第一轮 | 单张比大小 / 十点半 / 飘三叶 | 1 + 2 + 3 = 6 |
| 第二轮 | 单张比大小 / 斗牛 | 1 + 5 = 6 |

每组**独立结算**——单独比、单独收分，互不影响。每人**从 0 分起算**，
一把里分数不封顶也不补：赢多少都留着，输了也负着继续打。**净胜 = 最终分。**

| 组 | 赢家收每人 | 怎么算赢 |
|---|---|---|
| 单张比大小 | 1 分 | A 最小，2..K 递增，大王最大；同点比花色 ♠ > ♥ > ♣ > ♦ |
| 十点半 | 1 分（正好 10.5 收 2 分） | 超过 10.5 爆点，爆点的人排在不爆的人后面 |
| 飘三叶 | 1 分起，豹子加成 | 豹子 > 同花顺 > 同花 > 顺子 > 对子 > 散牌 |
| 斗牛 | 五花牛 4 / 牛牛 3 / 牛 8-9 收 2 / 牛 1-7 收 1 | 见下方「容易算错的地方」第 2 条 |

### 大王在四种牌组里的身份，各不相同

- **单张比大小**：它本身就是最大的一张牌。
- **十点半**：能当 10，而且**比任何真 10 都大**——「王 + K」也是十点半。
- **飘三叶**：万能，自动凑出最优牌型。
- **斗牛**：两处都能补——能去凑「三张成 10」，也能留在剩下两张里凑牛牛；
  但比大小时**不拿王比**，取除王以外最大的那张。

### 同分怎么分胜负

- **单张比大小**：比花色 ♠ > ♥ > ♣ > ♦。
- **十点半**：同点数时，先比**贡献点数的牌谁大**（7+A 与 4+4 都是 8 点，比的是那张 7 和那张 4），
  贡献点数相同再比花色；王当的 10 算最大。
- **飘三叶**：先比牌型，同牌型比点数，再比花色。**注意 A 在飘三叶里是最大**（A23 是最小顺子，
  但散牌/对子里的 A 按 14 算）。
- **斗牛**：先比五张里最大的牌（**K > Q > J > 10 > … > 2 > A**，A 算 1 最小），
  再从大到小逐张比，牌全同比花色。

### 五个容易算错的地方

这五条是规则实现里真实存在、但旧版文档没说清或说错的。**以本节为准。**

| # | 容易错在哪 | 实际规则 |
|---|---|---|
| 1 | 以为「J/Q/K 在斗牛里一样大，只是半点」 | **斗牛比大小时 K > Q > J**（`engine.js` `douNiuCompareRank`）；只有**算牛几的点数**时它们才算 10 |
| 2 | 以为「没牛的人一定多付 5 分」 | 只有**赢家有牛**时，没牛的人每人才多付 5 分；**全员没牛**时赢家只收 1 分，没人被罚 |
| 3 | 以为「超过 10.5 就判负、这组没人赢」 | 零和规则下必有人赢：**全员爆点时，爆得少的人赢**，照样收 1 分/人 |
| 4 | 以为「王 + 四张花牌 = 五花牛」 | 五花牛要求**五张全是真花牌**；带王只走牛牛分支，判 **牛牛（3 分）**，不是五花牛（4 分） |
| 5 | 不知道「排出的十点半会爆」时提交会被拦 | 有**爆点拦截**：排出的组合爆点、且手里还有不爆的打法时，提交会被挡下并弹窗让你改。这是全游戏唯一一处「系统主动纠正你的分法」 |

## 一场对局会怎么走

```
进房 → 第一轮分牌 → 结算 → 第二轮分牌 → 结算 → 这一把打完
     → 没打满：直接开下一把，分数延续
     → 打满建房时选的把数：整局结束（默认 10 把，可选 3 / 5 / 10 / 15 / 30）
     → 结算页：点一下「开始下一把」就算报名兼就位（v116 起一次点击，
       不再需要回房间再点一次准备）
     → 开不开由「**房间里所有真人都表过态**」决定（v121）：有人还在看结算页就等他，
       想先开只有一条路 —— 明确「不等他」，或者对方自己点「这把不打」
     → 被落下的人**不会被踢出房间**：座位和分数都留着，别人开打后他以「旁听」
       身份留在牌桌边（v118），这一把结束后回结算页，再点「开始下一把」就能上场
     → 结算页还能改「下一局打几把」（房主，3 / 5 / 10 / 15 / 30 档，改了从下一局算）
     → 中途想停：谁都能提请「结束本局」，全员同意就结束（一分没打不计战绩）
```

**术语**：一律用「把」——**一把 = 两轮**，打满建房时选的**把数**就结束整场（「本局」）。
界面文案 v109 已全部对齐（原先建房弹窗问「打几局」、顶栏说「第 3/10 把」，同一件事两种说法）。

把数在建房时定，**房间内不可改**；结算后继续游戏沿用同一档位（分数**重置回 0**）。
顶栏一直显示「第 3/10 把」，结束点看得见，不用猜还要打多久。

正常终局**只有一种：打满把数**。另外两条是异常收尾——人数不足（有人弃局走了）、
中途全员同意结束。**没有「分数见底就结束」这条规则**（v103 删除，原因见迭代史）。

### 分是**按组**算的，但**按轮**一起揭晓

一把牌 6 张，分两轮用：第一轮拆成「比大小 / 十点半 / 飘三叶」三组，
第二轮拆成「比大小 / 斗牛」两组。**每组都是一个独立的输赢**：

| | 第一轮 | 第二轮 | 一把合计 |
|---|---|---|---|
| 比几次 | 3 组各比一次 | 2 组各比一次 | **5 次** |
| 赢家 | 每组一个，可以都不是同一个人 | 同左 | — |
| 加减分 | 每组各算各的 | 同左 | 5 次累加 |

但**不是每组结束就比一次**：三组的分牌要一起提交（6 张必须刚好用完），
全员提交后状态机一次性把三组算完，只弹一张「第一轮结算」，三组按 0.35s 错峰揭晓。
所以玩家看到的节奏是「分牌 → 一次结算看三组」，不是「分一组、比一组」。

- **分牌 60 秒**，超时本回合弃权：人还在房间，下一把照常玩。
- **断线 90 秒**宽限，超时判弃局，座位释放。
- **弃权 ≠ 弃局**。弃权只是这一轮难看；弃局要把座位让出来，
  剩余人数不够会直接结束整局（2 人局等于整局没了）。
- **输定了就跑不会免罚**：弃局按离开那一刻的分数记进战绩。

### 成就：39 条，记的是「次数」

| 系列 | 条数 | 记什么 |
|---|---:|---|
| 牌型 | 8 | 5 种大牌型（五花牛 / 同花顺 / 豹子 / 牛牛 / 十点半）+ 3 种小牌型（爆点 / 散牌 / 没牛），每种一条、给**次数 + 出现率**；分母是「参与该组的次数」，不是打了多少把 |
| 对撞 | 8 | **对称八条**：大牌撞大牌（硬茬子 赢的次数 / 软脚虾 输的次数 / 遇强则强 胜率 ≥46% / 外强中干 胜率 <34%）+ 小牌撞小牌同构四条（宁为鸡头 / 鸡飞蛋打 / 矮子里拔将军 / 矬子里垫底，条件是**全场都是小牌**）。胜率型四条另加样本门槛（大牌对撞 ≥100 次、小牌对撞 ≥30 次），34%~46% 是真空区，两条都不亮 |
| 通吃 · 通赔 | 8 | 通吃 4 条（三组全赢 / 两组全赢 / 五组全赢 / 通吃十次）+ 通赔 4 条一一对应（三组全输 / 两组全输 / 五组全输 / 通赔十次） |
| 战绩 | 15 | 场次阶梯（1 / 10 / 50 / 100 / 200）、连胜（5 / 10 / 15）、连败（5 / 10）、单场上限 150 分（单场之王）、一场净胜 >100 的次数（一夜暴富）、全场唯一正分（你咋这幸，**≥3 人局**才算）、全场唯一负分（我咋这霉）、连败后赢一把（翻身农奴） |

**数字怎么显示**：九条画进度条（常客 10 / 熟面孔 50 / 老油条 100 / 铁人 200 场，
势不可挡 5 / 十连胜 10 / 十五连胜 15 场连胜，背到极点 5 / 衰神附体 10 场连败）——
它们的语义是「还差多少」。其余全部写「37 次」这样的累计数，玩得越久数字越大，
不会顶在 20/20 上不动。

**门槛不是一进门就发**：次数型成就的门槛 3~5 次起（v116 从 1 抬上来的），
所以打完**第一把只亮 1 条**（「第一次」）。以前是 5 条起步，等于注册礼包。
稀有度标签（★ 的档位）按线上实测解锁率标定，不是拍的 —— 见 `scripts/ach-unlock-stats.js`。

成就**从本功能上线那天开始记**：历史对局没有存牌型，回不去。
换设备不影响（服务端档案里）；2026-11-11 起服务端另存原始观测事件，改口径可以重放（见下）。

## 跑起来

需要 **Node.js ≥ 18**，没有其他依赖，也没有构建步骤。

```bash
npm start                              # 本地起服务，默认 3000 端口
npm test                               # 全量回归：169 个文件 / 7024 条断言，约 120 秒（含文档一致性守 39 项）
npm run docs:check                     # 只跑文档一致性守：死链 / 版本卡片 / 生成式台账 / 现行规格唯一
node scripts/journey.js                # 真实浏览器走一遍完整用户路径
node scripts/probe-devices.js --assert # 机型支持：三族 23 档，不达标退出码非 0
node scripts/probe-ui-flow.js          # 全流程 UI 巡检：12 视口 × 13 屏，约 22 分钟
node scripts/probe-admin.js            # 管理后台全链路：起任务 → 跑完 → 逐把明细 → 排行榜，约 40 秒
node scripts/probe-online-smoke.js     # 发布后核对线上（15 条硬断言，需要线上地址与口令）
node scripts/ach-baseline.js           # 冻结成就基线（一次性，幂等；见下「成就口径变了怎么重算」）
node scripts/replay-achievements.js    # 用事件日志按当前口径重算成就，默认只打 diff
```

规则数值全在 [`pwa/js/config.js`](pwa/js/config.js)，改一个数双端同时生效。

### 管理后台

`/admin.html`（不需要登录账号，需要服务端那把 `x-backup-key`）。三个页签：

- **用户管理**：改昵称、重置密码、停用、删号
- **模拟对战**：勾选 2～5 个真实账号，定「场数 × 每场局数」与节奏，后台代打并把战绩真实写进排行榜；
  实时进度、逐场明细、逐把流水、榜单增量
- **排行榜**：全量名次（公开接口只给 top50）

> 为什么必须用真实账号：含 AI 的对局只进 `aiRecent`，排行榜与积分一概不动。
> 一个房间打满才落库 —— 「打 30 把」和「打 30 场」是两件事。
> 账号密码**只留在页面内存与任务运行期**，不进 `sessionStorage`、不写进任务历史文件。

### 成就口径变了怎么重算

档案里的 `ach` 是聚合计数器（`t.lp = 242` 这种），**不可逆** ——
它丢了「哪一把、第几轮、同桌有谁」，所以改判定以后回不去。

从服务端接入事件日志那一版起，服务端把**原始观测**另存一份 append-only 事件日志（`DATA_DIR/events/*.jsonl`）：

- `k:"g"` 轮级：一轮里每个人拿了什么牌型（原文 + 点数）、算哪一组、谁赢
- `k:"s"` 场级：全场每人净胜（**含 AI**），同时是「一场」的桶边界

于是：`当前值 = 基线 + fold(基线之后的所有事件)`，fold 用**当前这版** `achievements.js` 跑。
改阈值、改计数口径 = 改 fold + 重放一遍，历史自动翻转。

```bash
npm run backup                         # 先把 profiles.json 与 events 增量拉到本地（含 achBase）
npm run ach:baseline -- --apply        # 离线补冻基线（线上那次是启动时自动做的，见规矩 1）
npm run ach:replay                     # 预演，只打 diff
npm run ach:replay -- --apply          # 写回；--player <id> 只看一个人，--json 机器可读
npm run ach:reset -- --keys r9,r10,r12 # 定点清计数（判据写错的历史修正，默认只预演）
npm run ach:unlock-stats               # 按线上档案实测每条成就的解锁率，校准稀有度档位
```

三条规矩：

1. **基线越晚越安全**，不是越早。重放器会跳过 `t <= 基线时刻` 的事件（它们已经算进 counts 了），
   所以「基线晚于事件」只是重复一段、不会双计；危险的只有反过来 —— 基线早于日志，
   那段时间的牌既不在基线、也没有事件，重放会把它抹掉。所以顺序是「先发布打开日志，才谈得上基线」。
   这件事**服务启动时自动做**（`stampAchBase`，幂等）：线上容器没有远程 shell，
   而基线缺失时重放器会跳过所有人 —— 整套设施对真实玩家等于不存在，且没有任何症状。
2. **没有基线的档案一律跳过**，不从 0 起算 —— 那些人的 `ach` 是全部历史，拿事件重放等于抹掉它。
3. **重放不动 `achBase`**。基线被改写等于把历史第二次冻进去，重放一次涨一次，还没有任何症状。

日志写失败**绝不影响结算**（全程 try/catch），也能用 `EVENT_LOG=off` 整个关掉。
体积约 277 B / 把，一年量级 10 MB 上下。

**判据写错攒下的死数字**（比如「你咋这幸」比场次还多）用 `ach:reset` 定点清：
它同时清 `ach` 和 `achBase.counts` —— 只清前者，下次重放会把基线那份叠回来；
只清白名单里的战绩键（`r7`/`r8`/`r9`/`r10`/`r12`），因为 `vs`/`vsn`/`t.*` 是比率的**分母**，
清掉分母不是修正，是把那条成就永久废掉。接口默认 `dryRun`，要先看原值再 `--apply`。

## 数据与隐私

这个项目会保存账号与战绩，所以有必要写清楚：

- **存什么**：账号名 + scrypt 盐/哈希（**不存明文密码**）、昵称、可选头像、
  对局记录（场次/胜负/净胜/连胜、最近若干场含房号与结束原因）、时间戳。
- **不存什么**：不存明文密码，不用手机号注册，不接第三方统计，不收集设备标识。
  IP 只在内存里做登录与进房限流，不写进档案（但服务端日志会记录连接 IP，部署侧需自行处置）。
- **删号**：账号页可自助注销，会级联清掉服务端档案与本机战绩/回放。
- **公开仓库不含真实玩家数据**：仓库里只有 [`server/data/profiles.example.json`](server/data/profiles.example.json)
  这种结构样例，真实数据靠 `DATA_DIR` / `SEED_FILE` 指向仓库外。
